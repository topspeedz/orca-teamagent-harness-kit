# 기반 설계

> **읽는 시점:** setup 스킬 6단계. Orca 틀을 깔았든 깔지 않았든 같다.

기반 하네스는 에이전트가 작업에 필요한 정본만 찾아 읽고, 되돌리기 비싼 행위 앞에서 멈추고, 끝났다고 말하기 전에 검증하게 만드는 구조다. 문서를 많이 쓰는 일이 아니다. 근거는 [principles.md](principles.md), 복사해 쓸 뼈대는 [templates.md](templates.md), 도구 함정은 [pitfalls.md](pitfalls.md)에 있다. 해당 단계에서만 연다.

설계는 제안이다. 파일을 만들거나 설정을 바꾸기 전에 단계마다 범위를 보여 주고 진행한다. 권한 완화, 훅 등록, 전역 설정은 먼저 승인받는다.

## 1. 인벤토리와 V1

1. 기존 지침: `CLAUDE.md`, `AGENTS.md`, `.claude/**`, `.cursor*` 등. 있으면 크기와 역할.
2. 실제 검증 명령: `package.json` scripts, Makefile, CI workflow. **없는 lint·test 명령을 지어내지 않는다.**
3. 문서: md 개수와 위치, 30KiB 넘는 파일, 날짜 붙은 이력 문서.
4. 위험 표면: 배포, push, DB, 외부 API, 대량 삭제가 가능한 명령.
5. 세션 기록이 있으면 프로젝트 루트에서 측정한다. 처리 토큰 합계는 대부분 캐시 읽기라 비용 판단은 출력의 환산값으로 한다.

   ```sh
   node "${CLAUDE_PLUGIN_ROOT}/skills/setup/scripts/measure-token-usage.mjs" 7
   ```

6. **V1 — 찾은 검증 명령을 한 번씩 실제로 돌려** 명령, exit, 소요 시간, 통과/실패를 표로 남긴다. 이미 실패하는 명령을 완료 게이트로 지정하면 첫날부터 게이트가 무의미하다. 실패 목록을 기준선으로 고정하거나 게이트에서 뺀다. 부작용(배포, DB 쓰기, 유료 API)이 있거나 오래 걸리는 명령은 돌리기 전에 묻는다.

인벤토리로 답할 수 없는 것만 한 번에 묻는다.

- 어느 세션에서도 금지할 명령은 무엇인가(운영 배포, 대량 삭제 등). 사람 승인이 필요한 명령은 setup 2단계에서 이미 물었으면 다시 묻지 않는다.
- 이 프로젝트에서 반복해서 시간을 잃은 실수가 있는가. 첫 규칙의 재료다.

## 2. T0 라우터 (항상 로드되는 층)

- Orca 틀을 깔았으면 깔린 `AGENTS.md`의 `명령`, `기술 스택`, `핵심 원칙`, `작업별 라우팅`을 채운다. `CLAUDE.md`는 `@AGENTS.md`와 Claude 전용 내용만 둔다.
- 깔지 않았으면 [templates.md §1](templates.md)의 뼈대로 `CLAUDE.md`를 쓴다. Codex 같은 다른 런타임과 함께 쓰면 공통 규칙은 `AGENTS.md` 하나에 두고 `CLAUDE.md`는 `@AGENTS.md` 한 줄과 Claude 전용 내용만 둔다.
- **담는 것:** V1에서 돌려 본 명령, 기술 스택 한 단락, 이 프로젝트 고유의 원칙, 코드 스타일, "작업 → 첫 문서" 라우팅 표.
- **담지 않는 것:** 값, 표, 이력, 장문 예시, 특정 작업 전용 절차. 그것은 가리켜진 문서가 소유한다.
- 예산은 `/context`의 실제 토큰으로 잰다(한글은 바이트당 토큰 비율이 달라 bytes는 근사다). 출발점은 다른 런타임과 공유하면 13KiB 안팎, 단독이어도 20KiB 이하다. T0 1만 토큰은 모든 턴에 곱해진다([principles.md §1](principles.md)).
- `.claude/rules/*.md`는 `paths:` frontmatter가 없으면 `CLAUDE.md`처럼 항상 로드된다. 쪼개도 T0는 줄지 않는다. 특정 경로에서만 필요한 규칙은 `paths:`를 달거나 그 폴더의 `CLAUDE.md`로 내린다(그 폴더 파일을 읽을 때만 로드). 항상 필요한 규칙은 발동 조건과 금지만 적고 상세는 문서로 내린다.
- 한쪽 런타임에서 다른 쪽으로 파일을 생성·미러링하는 장치(변환기, manifest, 동기화 훅)는 두지 않는다. Claude 전용은 `.claude/`, Codex 전용은 `.codex/`와 `.agents/`에 두고, 둘 다 사본이 아니라 그 자리의 원본이다. 양쪽이 쓰는 스킬은 원본 `.claude/skills/<이름>`에 두고 `.agents/skills/<이름>/SKILL.md`는 frontmatter와 "본문은 원본 경로를 읽는다" 한 줄만 둔다. 저장소 안에는 정션을 두지 않는다. git과 새 워크트리가 재현하지 못한다.

**범위 모드(하네스가 있는 저장소의 새 모듈):** 그 폴더의 `CLAUDE.md` 또는 `paths:`를 단 `.claude/rules/<모듈>.md` 하나와 루트 라우팅 표의 한 줄만 만든다. 루트 설정과 훅은 상속하고 건드리지 않는다. 검증은 V1과 V4만 한다.

**빈 저장소(코드와 명령이 없다):** `CLAUDE.md` 한 장에 한 줄 정의, 정해진 스택, "검증 명령은 스택 확정 후 추가"만 적는다. 나머지는 코드가 생긴 뒤에 한다.

## 3. 문서 계층

역할은 router / canonical / contract / runbook / spec / history 여섯 개면 충분하다([principles.md §2](principles.md)). 처음부터 다 만들지 않는다.

1. router는 문서가 실제로 여럿일 때만, 도메인당 하나씩 1~2개로 시작한다. 각 router의 끝은 코드 경로나 검증 명령이어야 한다.
2. 활성 문서 첫 화면에 상단 계약 3줄을 둔다: 읽는 시점, 역할과 소유 범위, 소유자와 상태([templates.md §2](templates.md)).
3. 날짜 붙은 계획과 사고 기록은 history 폴더로 분리하고 본문을 고치지 않는다. 현재 규칙과 섞어 읽히면 안 된다.
4. 깊이는 T0 → router → canonical → 코드, **3단을 넘기지 않는다.**
5. 링크, 예산, 상단 계약을 검사하는 `verify-docs` 류 스크립트는 깨진 링크나 예산 초과가 실제로 한 번 나온 뒤에 만든다.

## 4. 게이트: 안내와 강제를 구분한다

| 막으려는 것 | 수단 |
|---|---|
| 끝났다고 하기 전에 검증 누락 | T0 규칙 "완료 흐름"([templates.md §3](templates.md)). 반복해서 빠진 증거가 생기면 `Stop` 훅으로 올린다 |
| 어느 세션에서도 금지(force push, 운영 배포, 대량 삭제) | `permissions.deny`. bypass 모드에서도 막힌다. Orca 틀은 force push를 이미 막아 두었으므로 1단계에서 답받은 것만 더한다 |
| 사람 승인이 필요(배포, 유료 API) | `permissions.ask`. 대화형 세션은 실제로 묻는다. bypass 세션(무인 워커)에는 ask가 적용되지 않으므로 훅 deny를 함께 둔다([templates.md §4](templates.md)) |
| 정본과 문서의 드리프트 | 코드 옆 `*.check` 스크립트와 `verify-*` 명령. 정본을 옮기는 작업에는 그 정본을 읽는 check 갱신을 포함한다 |
| 조용한 실패 | fallback과 필터로 누락을 감추는 코드를 리뷰 대상으로 지정한다 |

훅에는 fail-closed(파싱 실패도 deny) 여부를 명시하고 셀프테스트를 같이 둔다. matcher는 셸 도구를 모두 잡는다(`Bash|PowerShell`). 도구 선택 같은 행동 교정에는 deny 훅을 쓰지 않는다([principles.md §3](principles.md)).

## 5. 위임은 필요할 때만

기본은 **인라인 직접 처리**다. 이 스킬은 팀과 에이전트를 만들지 않는다. 에이전트와 스킬은 같은 절차가 반복된 증거와 독립 책임이 생긴 뒤에 만든다([principles.md §5](principles.md)). Orca 틀을 깔았으면 `docs/harness/templates/`의 양식으로 직접 추가한다.

## 6. 측정과 성장 규칙

- 기준선은 첫날 `/context`(T0 토큰 내역)와 `/memory`(로드된 지침 파일)로 잡는다. 세션 기록이 쌓이면 1단계의 측정 스크립트를 돌린다.
- 구조를 바꾸기 전후로 같은 측정을 돌려 표로 남긴다. **효과가 확인되지 않은 규칙을 T0에 쌓지 않는다.**
- 증거가 생기면 추가할 것:

| 추가물 | 조건 |
|---|---|
| 자동 압축 창 `CLAUDE_CODE_AUTO_COMPACT_WINDOW`([templates.md §1](templates.md)) | 1M 컨텍스트 모델에서 20만 넘는 턴 비중이 측정상 클 때. 사람마다 모델이 다르므로 `settings.local.json`의 `env`에 둔다 |
| T0 `## Compact Instructions` | 압축이 실제로 일어나는 긴 세션. Orca 틀의 `AGENTS.md`에는 처음부터 있다 |
| 헤맴 회고 규칙([templates.md §5](templates.md)) | 같은 대상을 여러 번 찾아 헤맨 세션이 반복 측정됐을 때 |
| `verify-docs` | 3단계 5 |
| `Stop` 훅 | 4단계. 완료 전 검증 누락이 반복될 때 |
| DAG 병렬 지표 | Orca Run 장부가 쌓이기 시작하면 Run마다 잰다(Orca 틀의 `harness-retro` 스킬) |

## 산출물

1. **설계안:** 범위 판정, T0 목록과 `/context` 토큰, router 표(작업 → 첫 문서 → 다음 문서 → 코드/검증), V1 표, 게이트 표(deny, ask, 훅 구분).
2. **1일차 최소:** 돌려 본 명령이 든 T0(범위 모드면 그 파일 하나), 위험 명령의 `permissions.deny`/`ask`, 완료 흐름 3줄. 나머지는 6단계 조건표를 따른다.
3. **기준선:** `/context` 수치와 측정 결과, 또는 측정 불가 사유.
4. **하지 않기로 한 것:** 지금 만들지 않는 에이전트, 스킬, 훅과 추가 조건.

## 구축 후 검증

| | 하는 일 | 통과 기준 |
|---|---|---|
| V1 | 1단계 명령 표를 구축 뒤 다시 돌린다 | 완료 게이트 명령이 기준선과 같은 결과 |
| V2 | 새 세션에서 `/memory`와 `/context` | 설계안의 파일만 로드. 범위 모드 파일은 그 폴더 파일을 읽기 전엔 없다 |
| V3 | deny와 ask 대상을 무해한 형태로 하나씩 시도(예: `git push --force --dry-run`) | deny는 막히고 ask는 묻는다. bypass 세션에서는 훅이 막는다 |
| V4 | 새 세션에서 대표 작업 2~3개를 주고 `required / actual / forbidden` 문서를 기록 | required 전부 읽힘, forbidden 0. 데이터 작업에 UI 이력이 읽히면 라우팅 실패 |

V2와 V4는 새 세션이 필요하므로 사용자에게 방법을 알리고 결과를 받아 적는다. 실패하면 해당 라우터와 설정을 고치고 그 항목만 다시 돌린다. 최대 2회, 그래도 실패면 증거와 함께 보고한다.
