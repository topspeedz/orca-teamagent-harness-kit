# 원칙과 실측 근거

출처는 실제 프로젝트 두 곳의 실측이다. 수치는 그 프로젝트의 것이므로 **방향**으로 읽고, 새 프로젝트에서는 직접 측정해 대체한다.

## 1. 비용의 단위는 턴 수 × 그때의 컨텍스트다

- 도구 1회 = 1턴 = 컨텍스트 전체 재독. grep 결과 1건은 약 700토큰이었지만 그 턴의 재독은 평균 265k였다.
- 7일 144세션에서 처리 토큰의 78%가 컨텍스트 20만 초과 턴에서 나왔다. 주범은 md 조회가 아니라
  **세션 비대화**(자동 요약 기본값이 너무 큼)와 **코디네이터의 주기 폴링**이었다.
- 처방 순서: ① 자동 요약 창 축소 ② 독립 조회를 한 메시지에 묶기 ③ 워커·세션을 작게 ④ 폴링·heartbeat 대신 완료 알림 대기
  ⑤ 그 다음에야 T0 축소. T0 고정분 1만 토큰 ≈ 턴 수만큼 곱해진다(주 1만 턴이면 1억 토큰).
- 한 번 들어온 큰 출력(파일 통독·스크린샷·로그)은 세션이 끝날 때까지 매 턴 다시 읽힌다 — 범위 읽기, 또는
  서브에이전트가 읽고 결론만 반환.
- **liveness 신호와 알림도 턴이다.** 워커가 주기 heartbeat를 독립 명령으로 보내면 전송 턴 + 결과 턴 2번의
  재독이 들고, 그 메시지가 코디네이터를 다시 깨운다. 14일 184세션 실측에서 이 경로가 재독의 11.7%였고
  코디네이터 깨움의 73%는 heartbeat만 담고 있었다. 런타임이 훅으로 이미 턴을 관측하면 heartbeat는 중복이다.
- 세션 시작 주입물(메모리 요약·플러그인 컨텍스트)은 크기가 아니라 **조회 횟수**로 판정한다. 30일 688세션에 주입됐는데
  조회가 4회였던 메모 목록은 껐고, 검색 경로("되묻기 전에 검색")만 규칙으로 남겼다.
- 서브에이전트로 옮긴 비용은 메인 수치에서 사라질 뿐이다. 측정은 sidechain을 따로 합산해 "절감"으로 오인하지 않는다.

## 2. 문서 계층

| 역할 | 책임 |
|---|---|
| router | 작업 조건과 다음 문서만 안내. 값·계약을 갖지 않는다 |
| canonical | 한 주제의 현재 단일 출처 |
| contract | 불변식·인터페이스·데이터 규격 |
| runbook | 명령과 실행 순서 |
| spec | 사용자 가시 목표 상태 |
| history | 날짜 붙은 계획·사고 기록. 본문을 고치지 않고 상태·대체 정본만 표시 |

- 목표는 문서 수·용량 축소가 아니라 "필요한 정본만 발견하고 현재 규칙과 이력을 섞어 읽지 않는 것".
- 온디맨드 문서로 내렸으면 **도달 경로를 반드시 남긴다.** 경로 없는 축약은 삭제와 같다.
- 읽기 조건·소유자·수명이 다르면 분할, 항상 같이 읽고 같이 바뀌면 합친다.
- 파일 하나 30KiB 안팎. 넘으면 기존 경로·앵커를 router로 남기고 독립 주제만 하위 canonical로 옮긴다.
- 모든 항로의 끝은 실행 가능한 것(코드 경로 또는 검증 명령)이어야 한다.
- 실측에서 이 구조는 건강했다: 코드 수정 세션 27개 중 23개가 첫 수정 전에 정본을 조회, 없는 경로 Read는 7일 3건.
- 이동·분할 시: 코드·훅·설정까지 inbound 참조 검색 → 옛 경로를 router로 유지하거나 전부 갱신 → 원문 삭제 금지.

## 3. 안내는 강제가 아니다

- 표면을 guidance / enforcement / runtime state / generated로 분류한다. Markdown을 고쳐서 권한·차단 문제를 풀 수 없다.
- 금지는 `permissions.deny`(모든 모드에서 적용), 사람 승인은 `permissions.ask` + bypass 세션용 훅 deny.
  bypass 모드에서는 `ask`가 적용되지 않는다. 에이전트가 만들 수 있는 플래그 파일은 승인이 아니다.
  오탐(명령 문자열에 패턴이 들어 있기만 해도 차단)은 감수할 대가로 문서화한다.
- 게이트 훅은 fail-closed(payload 파싱 실패도 deny), 편의 훅은 fail-open(판단 실패는 통과). 어느 쪽인지 표에 적는다.
- 훅 셀프테스트는 훅을 자식 프로세스로 돌려 payload를 주입하는 방식. OS 의존이면 로컬 전용임을 명시한다.
- 승인은 회차·범위 단위로 한정한다. 반대로 판단 없는 단계마다 승인을 요구해 무인 실행을 막지도 않는다.
- **강제 자체가 턴이다.** deny된 호출은 이미 재독을 치렀고 사유가 다음 턴을 만든다. deny는 안전·데이터 경계에만 쓰고
  도구 선택 같은 행동 교정에는 쓰지 않는다 — 복합 명령 전체가 날아가 재실행되고 다른 명령으로 우회돼 순손해가 된다.
- 규칙이 항상 로드돼도 워커가 안 따르면 없는 규칙이다. 워커 전용 지시는 프롬프트 직후에 주입(UserPromptSubmit)하는
  편이 T0에 한 줄 더 얹는 것보다 싸고 잘 읽힌다.

## 4. 정본 하나, 검사기 하나

- 공유 상수·헬퍼는 등재 문서 하나에 모으고 재정의·하드코딩을 금지한다.
- 규칙에서 값을 복사하지 않는다 — 규칙은 포인터, 값은 정본. 복사하면 같은 규칙이 두 곳에서 어긋난다.
- 정본을 옮기면 그 위치·형식을 하드코딩한 check 스크립트가 **나중에** 터진다. 이동 작업 범위에 check 갱신을 넣는다.
- 규칙을 바꿨으면 같은 주제를 말하는 다른 문서를 **표현 2~3개로 바꿔** grep한다(한 표현으로는 놓친다).
- 규칙의 실행 주체(워커·서브에이전트·훅)가 그 파일을 실제로 읽는지 따진다. 안 읽는 규칙은 없는 규칙이다.
- 다른 런타임과 지침을 공유할 때는 공통 규칙을 `AGENTS.md` 한 곳에 두고 `CLAUDE.md`가 `@AGENTS.md`로 가져온다.
  한쪽에서 다른 쪽으로 사본을 **생성**하는 장치는 두지 않는다 — 사본은 어긋나고, 어긋남을 맞추는 장치가 계속 는다.
  전용 기능은 각 런타임 자리의 원본이다([foundation.md](foundation.md) 2단계).
  런타임마다 로드 모델이 다르다 — Codex는 `AGENTS.md` 체인을 시작에 eager 로드하고 예산 초과분을 파일 단위로 버린다
  ([pitfalls.md](pitfalls.md) 설정·발견). 공유 T0는 가장 좁은 런타임의 예산에 맞춘다.

## 5. 성장 규칙

- 신규 에이전트·스킬·설정은 **반복 증거와 독립 책임**이 생기기 전에는 추가하지 않는다(Orca 틀이 처음부터 까는 것은 제외).
  사람의 반복 부담은 대개 새 자동화보다 기존 진입점을 한 runbook에 연결하는 것으로 풀린다. 새 **역할**(에이전트)은 세 증거가
  모두 있을 때만 — ① 반복: 같은 종류의 Task가 서로 다른 Run에서 2회 이상(리포트 경로로 증명) ② 분리: 기존 역할과 편집 범위
  또는 산출물이 다르다(같은 파일을 두 역할이 만지면 역할이 아니라 등급 문제) ③ 절차: 전용 스킬이 있거나 필요하다(기존 스킬
  한 절로 끝나면 스킬 보강). 하나라도 없으면 같은 역할 ×N 워커로 충분하다.
- 효과가 측정되지 않은 규칙은 T0에 넣지 않는다. 같은 지시가 기본 시스템 프롬프트에 이미 있으면 중복 규칙의 한계 효과는 불확실하다.
- 산문 규칙은 읽고 잊힌다. 반복해서 빠뜨리는 항목은 했다/안 했다를 답하는 체크리스트로, 그래도 빠지면 훅으로 올린다.
- 제안만 하고 채택되지 않은 발견은 백로그에 남긴다 — 대화에 묻히면 사라진다.
- 2회 실패 = 방식 교체. 같은 지점을 두 번 잘못 추정했으면 증상 패치를 멈추고 수집 지점을 바꾼다.
