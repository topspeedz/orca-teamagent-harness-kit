# Domain Patterns — 직무 특성별 조건부 확장

> Agent에 전부 넣지 않는다. 해당 직무에서 실제로 판단을 바꾸는 원칙 3~6개만 선택한다. 긴 문헌 목록은 별도 Reference로 둔다.
> 아래는 **조사 질문과 판단 패턴의 예시**이지 최신 공식 지식의 대체재가 아니다. 심화 설계는 [전문성 조사 프로토콜](./expertise-research-protocol.md)을 사용하여 프로젝트 버전·공식 근거를 확인하고, 역할 비교는 [6개 Agent 컬렉션 조사](./agent-corpus-research.md)를 조건부로 사용한다.

## 1. Mobile / Web UI Designer

- 요구사항 → 화면 상태 목록(empty/loading/error/success) → 사용자 흐름 → 컴포넌트 명세 순으로 연결한다.
- 디자인 시스템의 토큰·브레이크포인트·인터랙션을 우선 재사용한다. 새 컴포넌트는 기존 구성요소로 표현할 수 없을 때 정의한다.
- 접근성(키보드/터치 타깃/명도 대비/동작 감소)과 플랫폼 가이드의 해당 버전을 확인한다.
- 산출물: 화면 명세, 컴포넌트 props·state·variant·responsive behavior, interaction spec, QA 시나리오, 근거/변경 이유.
- 검증: 요구사항 추적, 상태 커버리지, 기존 패턴 일관성, 실제 렌더링/프로토타입 확인 여부.

## 2. Unity Gameplay / C# Developer

- Unity·패키지 버전과 타깃 플랫폼을 먼저 확인하고 해당 버전 API를 기준으로 구현한다.
- `Update` 핫패스의 할당, 물리 루프, 오브젝트 생명주기, 씬/Prefab 참조, 메인 스레드 제약을 설계 판단에 반영한다.
- 테스트: EditMode/PlayMode, 빌드, 성능 프로파일링은 실행 환경과 변경 범위에 맞게 구분한다.
- 산출물: 코드, 테스트, 영향받는 컴포넌트·씬, 실행·재현 절차, 성능 측정/제약.

## 3. Unity VFX / Shader Artist

- 타깃 디바이스·프레임 예산·렌더 파이프라인에 따라 VFX Graph/Particle System/Shader Graph 선택을 정당화한다.
- 텍스처 해상도·파티클 수·오버드로우·드로우콜·셰이더 변형을 품질과 비용의 트레이드오프로 관리한다.
- 시각적 충실도뿐 아니라 카메라 거리, 다양한 조명, 모션 중에서 확인한다.
- 산출물: VFX 에셋, 요구 셰이더/텍스처, 설정표, 씬 연결 방법, Before/After 및 Profiler 증거.

## 4. Blender 2D→3D Reconstruction Artist

- 입력 이미지의 화각·원근·렌즈 왜곡·보이는 기준점을 고려해 기하학을 추정한다.
- 실제 측정값, 이미지 기반 추정값, 미관상 가정을 반드시 구분한다. 보이지 않는 면을 확정 치수처럼 보고하지 않는다.
- 실루엣→주요 비율→2차 형상→재질→라이팅 순으로 개선하며 카메라 일치 및 멀티뷰 교차검증을 수행한다.
- 산출물: .blend/.fbx 등 요구 포맷, 축/단위/기준점, UV·머티리얼, 비교 렌더, 오차 및 불확실성 목록.

## 5. Game Designer / Systems Designer

- 핵심 플레이 루프와 의사결정, 위험-보상, 공정성, 온보딩, 반복 플레이의 동기를 구분해 설계한다.
- 재미를 무근거한 주장 대신 플레이테스트 가능한 가설·기대 행동·검증 지표로 표현한다.
- 경쟁 장르를 연구할 경우 장르·플랫폼·대상 사용자·흥행 시기를 비교하고 IP 표현을 무단 복제하지 않는다.
- 산출물: 게임 루프, 룰 명세, 예외 규칙, 경제/밸런스 매개변수, 맵·기믹 상호작용, 테스트 계획.

## 6. Documentation / Requirements Agent

- PRD → SRS → 기능 명세/UI 명세 → 테스트 케이스 간 추적성을 관리한다.
- 승인된 결정, 제안, 열린 질문, 실제 구현 사실을 혼동하지 않는다.
- 프로젝트에 이미 쓰는 폴더 구조/문서 양식을 우선하고 임의로 정본을 복제하지 않는다.
- 산출물: 변경된 문서 경로, 요구사항 ID, 선행 참조, 신규/수정/삭제 내용, 미확정 결정.

## 7. QA / Reviewer Agent

- 배정 범위, 결함 ID 체계, 위험 등급, 재현 단계, 기대/실제 결과를 표준화한다.
- 리뷰는 실제 구현 변경과 분리하며 리뷰어가 테스트를 통과했다고 주장하려면 증거가 있어야 한다.
- 광범위한 재실행 대신 변경 영향과 위험에 맞춰 테스트를 선택한다.
- 산출물: 테스트 로그, 재현 스텝, 근거 파일/라인, 결함 우선순위, PASS/FAIL/NOT_RUN.

## 8. 심화 조사 시 도메인별 핵심 질문

| 분야 | 먼저 확인할 맥락 | 조사/판단 초점 | 검증 증거 예 |
| --- | --- | --- | --- |
| Mobile/Web UI | 대상 OS·브라우저·기존 디자인 시스템·접근성 목표 | 공식 플랫폼 가이드 버전, 상태·반응형·접근성 충돌 시 우선순위 | 화면/상태 명세, 프로토타입, 접근성 검사 |
| Unity Gameplay | Unity·패키지 버전, 타깃 플랫폼, 씬/입력/물리 구성 | 실행 주기, API 지원 범위, GC/스레드·테스트 전략 | 컴파일, EditMode/PlayMode, Profiler 로그 |
| Unity VFX | 렌더 파이프라인·디바이스·카메라·프레임 예산 | VFX Graph/Particle System 선택 조건, 셰이더·오버드로우 비용 | 타깃 기기 렌더 비교, GPU/CPU 측정 |
| Blender Reconstruction | 입력 이미지·카메라·축/단위·허용 오차 | 측정값 vs 추정값, 투영·가림, 모델링/토폴로지와 재질 선택 | 멀티뷰/실루엣 오차, 원본 대비 렌더 |
| Game Systems Design | 장르·플랫폼·유저·핵심 루프·경제 설계 | 공정성·위험 보상·학습 곡선과 반복 플레이 가설 | 플레이테스트, 밸런스 로그, 행동 지표 |
| Documentation | 기존 PRD/SRS·승인권·문서 소유권 | 정본 우선순위, 추적성, 변경 이력·미결정 상태 | 요구사항 ID, 변경 diff, 링크 검증 |
| QA/Reviewer | 변경 범위·위험 등급·가용 환경·테스트 기준 | 재현성, 회귀 범위·결함 우선순위·검증 불가 사유 | 재현 단계, 테스트/빌드 로그, 이슈 증거 |

조사 결과가 프로젝트 맥락을 바꾸지 못한다면 원칙을 늘리지 말고 기존 패턴을 사용한다.
