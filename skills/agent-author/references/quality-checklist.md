# Agent Definition — Quality Checklist

완성 Agent를 생성·수정할 때 적용한다. 점수는 문서의 품질을 가늠하기 위한 **설계 평가**일 뿐 실행 성공의 보증이 아니다.

## 필수 검증 (하나라도 실패하면 수정)

- [ ] YAML frontmatter 파싱 가능. `name`·`description` 누락 없음. 비지원/오타 필드 없음.
- [ ] `description`이 명확한 호출 조건과 차별화된 책임을 표현함.
- [ ] 역할·권한·출력·품질기준이 하나의 핵심 성과로 수렴함.
- [ ] 전문 분야의 고유 판단 규칙이 단순 역할 소개 이상으로 구체적이며, 조건·기준·행동·증거·실패 대응을 포함함.
- [ ] 필수 입력 또는 Source of Truth와 입력 부족 시 처리 규칙이 있음.
- [ ] Tool/Skill/MCP/모델/경로의 존재와 권한을 확인했거나 조건부로 표기함.
- [ ] 실제 하지 않은 검증을 완료로 보고하지 못하도록 설계함.
- [ ] 작업 실패 및 위험 변경의 승인/중단 조건이 있음.
- [ ] 다른 Agent와 함께 일한다면 Task 소유권, 종속성 및 Handoff 항목이 있음.
- [ ] 중복된 역할·스킬 전문 지식 복제·무의미한 표어/과잉 지침이 없음.

## 설치 프로젝트의 인수 확인

- 신규 정의에서 `node .claude/scripts/agent-definition.mjs --agent <name>`과 모델 표 검사를 실행한다. 스킬 더하기·스킬 본문 채우기·에이전트 만들기에서 이름과 작업 행이 하나씩 연결되고 Codex 선택 시 실제 TOML 본문과 포인터 도착 파일을 확인한다.
- 더하거나 채운 스킬마다 그 스킬의 `## 대표 사례`(정상 하나, 실패 하나)를 한 번씩 따라간다. 에이전트 정의가 아니라 스킬의 사례를 따라간다. 검토 기록에 요청 → 찾아 읽은 프로젝트 파일·지정 원문 → 선택과 사유 → 실행할 검사와 성공 증거 → 실패 시 보존·중단·협의 상대를 적는다. API 예시는 사용 중인 응답 필드 삭제와 소비자를 확인할 수 없는 경우다. 양식 통과나 아래 점수만으로 내용 검토를 마치지 않는다.

## 점수표 (0 미흡 / 1 일부 / 2 충분)

| 평가 항목 | 질문 |
| --- | --- |
| 책임 명확성 | 누구와 무엇이 다른가? |
| 전문 판단 | 무엇을 근거로 기술 선택을 하는가? |
| 워크플로우 | 실행 순서와 분기/실패 처리 기준이 명확한가? |
| 정보 정본 | 어떤 입력과 정책을 믿을지 명확한가? |
| 도구 현실성 | 실제 환경에서 작동할 설정인가? |
| 검증 가능성 | 완료 판정과 증거가 있는가? |
| 협업 계약 | 다음 Agent가 이어서 수행할 수 있는가? |
| 컨텍스트 효율 | 필수 지침만 상시 유지하는가? |

**권장 목표**: 총 14/16 이상, 필수 항목 전부 PASS. 낮은 점수의 항목만 구체적으로 수정한다.

## 전문성 심화 검증 (심화 설계 요청 시 추가)

- [ ] 사용자의 기술 요구와 프로젝트에서 확인한 버전·타깃·정본을 분리해서 기록함.
- [ ] 역할 고유의 주요 기술 선택 3개 이상에 적용 조건·트레이드오프·실패 대응과 검증 방법이 있음. 역할 특성상 적으면 이유를 설명함.
- [ ] 버전·공식 표준 의존 주장은 확인한 출처/범위를 갖거나 `UNVERIFIED` 상태로 유지함. 출처가 없는 주장에 공식 권위를 부여하지 않음.
- [ ] 검증된 사실과 프로젝트 정책, 가정과 근거 충돌을 구분함.
- [ ] 단순 정상 흐름 외에 관련된 기술 반례(버전 불일치·성능 회귀·도구 부재 등)를 통과하도록 지침을 작성함.
- [ ] 전문성을 확보하기 위해 불필요한 지식·긴 공식 문서를 Agent 본문에 그대로 복사하지 않음.
- [ ] 외부 Agent 컬렉션을 활용했다면 **관련 원문**을 직접 열람했고, 이름/README만 보고 전문성을 확인했다고 주장하지 않음.
- [ ] 6개 출처의 탐색 범위와 건너뛴 이유를 설명할 수 있음. 관련 후보는 역할 경계·판단·검증·인계 기준으로 비교했으며 KO/EN 중복·접힌 항목을 고려함.
- [ ] 외부 예제의 임의 숫자·절대 규칙·도구/모델 설정을 무검증으로 승격하지 않음. 채택 내용은 독자적으로 작성했으며 저작권/라이선스 위험을 검토함.

상세 근거 수집·판단 규칙 추출은 [전문성 조사 프로토콜](./expertise-research-protocol.md)과 [6개 Agent 컬렉션 조사](./agent-corpus-research.md)를 참고한다. **출처를 확인하지 못했으면 그 검사를 PASS로 표시하지 않는다.**

## 3가지 시나리오 테스트

### 정상 입력
승인된 SRS와 Task, 관련 도구가 주어진다. Agent는 할당 범위에서 산출물을 만들고 검증 증거를 반환해야 한다.

### 누락 입력/버전 충돌
레퍼런스가 없거나 프로젝트 버전과 공식 예제가 다르다. Agent는 임의 버전·도구를 만들어내지 않고 확인/합리적 가정/블로킹 중 적절한 선택을 해야 한다.

### 병렬 소유권 충돌
다른 Agent가 같은 파일을 수정 중이다. Agent는 직접 덮어쓰지 않고 소유권/통합 담당/순차 의존성을 재조정하도록 보고해야 한다.

```text
Follow-up: <연결할 Agent·Task·필요한 설치 작업>
```
