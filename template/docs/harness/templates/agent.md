# 에이전트 양식

setup과 agent-author는 설치된 이 파일의 코드 블록을 채워 `.claude/agents/<name>.md`에 저장한다. 전문 판단을 끌어내는 질문은 플러그인 agent-author의 `references/agent-definition-template.md`에 있다. 아래 안내와 자리표시자는 실제 결과에 남기지 않는다. 모델·effort는 모델 표에서 조회한다.

문서 책임과 직접 협업은 한 행에 한 경로·절·책임 또는 한 상대·주제·목적을 적는다. 적을 행이 없으면 표 머리와 구분선만 둔다. 입력에는 실제 읽는 파일 경로를, 산출물에는 앞으로 생성할 파일이나 Task 리포트를 적는다.

````markdown
---
name: <에이전트>
description: "<호출 조건과 책임, 관찰 가능한 결과>"
---

# <에이전트>

## 핵심 역할

<단일 핵심 성과와 인접 역할의 경계>

## 작업 원칙

- 로드할 스킬: `<프로젝트 역할 스킬>`
- 작업 단위: `<모델 표의 작업 단위>`
- <명단에서의 소속, 배정·편집·승인 경계, 확인한 도구>

## 전문 판단

<대표 요청의 조건, 결정 근거가 있는 실제 구현·참고 원문, 행동, 통과 증거와 실패 시 대응>

## 입력과 출력

### 읽는 입력

- `<프로젝트의 실제 입력 파일>` <읽는 이유와 필요한 내용>

### 작업 산출물

- <정본 또는 리포트의 경로와 보고 대상>

## 문서 책임

| 문서 | 범위 | 책임 |
| --- | --- | --- |
| `<정본 경로>` | <담당 절 또는 전체> | <작성/검토/확인 중 하나> |

## 직접 협업

| 상대 | 협의 주제 | 목적 |
| --- | --- | --- |
| `<상대 역할>` | <협의할 사실> | <협의가 필요한 이유> |

<spec의 수신 경로, 협의 상대 부재·범위 변경 시 배정자에게 올리는 경로>

## 완료 기준

<성공·실패를 판별하는 산출물과 검사, 미검증 항목을 남기는 위치>

## 다시 호출될 때

<이전 산출물·버전·미결 항목을 이어받는 방법>

## 오류 처리

<실패 신호와 복구 또는 중단·인계 기준>
````
