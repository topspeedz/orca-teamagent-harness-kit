# Task spec 양식

워커를 띄울 때 넘기는 spec이다. 첫 줄은 `[역할: <에이전트>]` 또는 `[역할: <에이전트> · 리드]`다.

```
[역할: <에이전트>]
Task: <Task ID> <이름>

목표: <한두 문장>

먼저 읽을 것:
- <경로와 범위>

편집 범위: <경로>. 그 밖의 파일은 만들거나 고치지 않는다.
금지: <하지 말 것>
배정: <에이전트> / <작업 단위> (<런타임> <model>/<effort>)
사용자 예외: <원문>

완료 기준: <검증자가 그대로 검사할 수 있는 값>
막히면: `ask`로 올리고 턴을 끝낸다. 사용자에게 직접 묻지 않는다.
보고: `worker_done` 본문 세 문장, 수정한 파일 목록, 리포트 경로 `_workspace/<팀>/<phase>/NN_<에이전트>_<산출물>_v<N>.md`. 리포트의 `## 검증` 절에 검증 줄을 ✅나 ❌로 적는다. 돌리지 못한 것도 ❌다. 완료 기준 밖의 줄은 `(참고)`로 시작한다.
```

## 쓰는 법

- `사용자 예외` 줄은 사용자가 이 Task에 다른 model·effort를 지시했을 때만 넣는다. 원문 그대로 적고 기동 스크립트에 `--override-reason "<원문>"`을 넘긴다.
- `배정` 줄은 모델 표에서 찾은 값이다. 팀장 spec(첫 줄 `· 리드`)의 배정 줄은 `배정: <에이전트> / 리드 (<모델 표의 `리드` 줄 값>)`이고, `--lead`로 띄울 때 `--unit`은 쓰이지 않는다. spec, 표, 기동 인자가 서로 다르면 기동이 거부된다.
- `완료 기준`은 검증자가 그대로 돌릴 수 있는 명령과 기대 출력이다. 구현 Task는 이 기준을 재현하는 테스트를 먼저 쓰고 실패를 확인한 뒤 구현한다.
- 워커는 사용자에게 직접 묻지 않는다. 막히면 `ask`로 코디네이터나 팀장에게 올린다.
- 워커는 커밋하지 않는다.
- 기다리는 단계를 `sleep`으로 쓰지 않는다. Claude Code가 단독 `sleep`을 막는다.
- Codex 워커에게는 기동 스크립트가 작업 방식 여섯 줄을 spec 끝에 붙여 넘긴다. 문장은 `worker-intake-context.mjs`가 정본이라 양식에 쓰지 않는다. Task를 먼저 만들고 `--task`로 띄우면 기동 스크립트가 붙이지 못하므로, `node .claude/scripts/orca-launch.mjs codex-rules`가 찍는 줄을 Task spec에 넣는다.
