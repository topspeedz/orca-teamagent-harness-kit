# 점검표와 감사 절차

> 읽는 시점: 작업 단위가 `문서 감사`일 때. 초기화와 동기화도 끝내기 전에 이 점검표를 읽는다.

## 범위

| 일 | 점검 범위 |
| --- | --- |
| `문서 감사` | 색인에 올라 있는 문서 전부 |
| `문서 동기화`, `문서 초기화`의 끝 점검 | 이번에 쓰거나 고친 문서 |

## 점검표

| 번호 | 볼 것 | 확인하는 법 | 어긋나면 |
| --- | --- | --- | --- |
| 1 | 색인의 모든 줄이 실제 파일을 가리키고, 번호 폴더의 모든 문서가 색인에 있다 | 색인의 정본 문서 칸마다 `test -f`, `ls docs/[0-9][0-9]-*/` | 고친다 |
| 2 | 문서에 나오는 모든 ID가 정의된 곳이 있다 | 아래 명령으로 쓰인 ID를 모으고, 정의하는 문서에서 찾는다 | 고친다 |
| 3 | 문서가 가리키는 코드 경로와 테스트 파일이 실제로 있다 | 근거 칸의 경로마다 `test -e` | 고친다 |
| 4 | 추적표에 빈칸이 없다: 테스트가 없는 요구사항, 요구사항이 없는 테스트 케이스, 코드 근거가 없는 `구현됨` | 추적표를 줄마다 본다 | 올린다 |
| 5 | 같은 사실이 두 문서에 서로 다르게 적혀 있지 않다 | `SKILL.md`의 정본 표 기준으로, 가리키기만 해야 하는 쪽이 값을 갖고 있는지 본다 | 올린다 |
| 6 | 계약 문서의 필드와 오류 코드, 화면 명세의 상태가 코드와 같다 | 계약과 화면 줄마다 근거 경로의 코드를 연다 | 올린다 |
| 7 | 모든 문서에 머리 네 줄이 있다 | `grep -L "마지막으로 갱신한 phase" <문서들>` → 나오는 파일이 없다 | 고친다 |
| 8 | 30KB를 넘는 문서가 없다 | `find docs/[0-9][0-9]-* docs/CODEBASE_MAP.md -size +30k` → 나오는 파일이 없다 | 고친다 |

쓰인 ID 모으기:

```sh
grep -rhoE "\b(US|FR|NFR|SCR|UI-FUNC|API|DATA|ADR|TC)-[A-Z0-9-]*[0-9]+" docs/[0-9][0-9]-* docs/DOCUMENTATION_INDEX.md | sort -u
```

- 7번에서 `docs/07-decisions/`의 ADR과 `docs/12-changelog/CHANGELOG.md`는 뺀다. 그 문서는 표준의 머리를 쓴다.

## 고치는 것과 올리는 것

- **고친다(1, 2, 3, 7, 8).** 문서 쪽의 사실 오류다. 끊긴 참조, 옛 경로, 빠진 색인 줄, 빠진 머리, 너무 큰 문서를 그 자리에서 고치고 리포트의 `## 고친 문서`에 적는다. 가리키던 코드가 없어졌으면 경로를 지어내지 않고 그 줄을 `확인 필요`로 둔다.
- **올린다(4, 5, 6).** 결정이 필요한 것이다. 어느 쪽이 맞는지 정하지 않고 리포트의 `## 불일치` 표와 `## 인박스 후보`에 적는다. 문서의 그 줄은 `확인 필요`로 둔다.
  - 4번에서 테스트가 없는 요구사항은 테스트를 쓰지 않는다. 빈칸으로 두고 올린다.
  - 5번에서 정본이 아닌 쪽이 값을 복사해 갖고 있고 두 값이 같으면, 복사한 쪽을 가리키기로 바꾼다. 이것은 고치는 것이다. 두 값이 다르면 올린다.

## 감사 리포트

`SKILL.md`의 리포트 형식으로 쓴다. `## 영향 분석` 대신 `## 점검 결과`(번호, 본 문서 수, 어긋난 수)를 둔다. `## 검증`에는 점검표의 줄마다 한 줄을 적는다.

- 어긋남이 없는 줄은 ✅로 적는다. 예: `- ✅ 3번 끊긴 경로 0건`
- 고쳐서 없앤 것도 ✅로 적는다. 예: `- ✅ 2번 끊긴 ID 3건을 고쳤다. 다시 돌려 0건`
- 올린 것은 `- ❌ (참고) 불일치 <N>건: <ID들>`로 적는다.
- 점검을 돌리지 못한 줄만 `(참고)` 없는 ❌로 적는다.

끝나면 색인의 문서 줄마다 상태를 고친다: 어긋남이 없으면 `최신`, 올린 불일치가 걸린 문서는 `확인 필요`.
