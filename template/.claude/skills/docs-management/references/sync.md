# 동기화 절차

> 읽는 시점: 작업 단위가 `문서 동기화`일 때. phase의 6단계에서 최종 테스트 뒤에 돈다.

지난 동기화 뒤에 바뀐 것만 문서에 반영한다. 여덟 단계를 순서대로 한다.

## 1. 변경 구하기

바뀐 파일은 넘겨받지 않고 git에서 구한다. 워커는 커밋하지 않고 phase 끝에 한 번에 커밋되므로, 색인을 마지막으로 고친 커밋이 지난 동기화의 경계다.

```sh
git log -1 --format=%H -- docs/DOCUMENTATION_INDEX.md   # 기준 커밋
git diff --stat <기준 커밋>                               # 그 뒤에 바뀐 추적 파일(커밋된 것과 안 된 것)
git status --short                                       # 새로 생긴 파일
```

- 아래 경로는 변경 목록에서 뺀다: `_workspace/`, `.claude/`, `docs/harness/`, `docs/history/`, 그리고 이 역할의 문서(`docs/DOCUMENTATION_INDEX.md`, `docs/CODEBASE_MAP.md`, `docs/`의 번호 폴더).
- `docs/superpowers/`의 설계서와 계획서, `docs/backlog.md`, `docs/backlog-archive.md`도 변경 목록에서 뺀다. 이들은 반영할 변경이 아니라 2단계에서 읽는 입력이다.
- 기준 커밋이 나오지 않으면 색인이 커밋된 적이 없는 것이다. 멈추지 않는다. 저장소에 커밋이 있으면 마지막 커밋 뒤의 변경을 범위로 삼는다(`git diff --stat HEAD`와 `git status --short`). 커밋이 하나도 없으면 작업 트리 전체가 범위다.
- git 저장소가 아니면 spec이 적은 경로만 본다.
- 색인의 문서 줄이 모두 `없음`인데 이번 변경 밖에 코드가 이미 있으면 초기화가 안 된 프로젝트다. 이번 변경만 문서로 만들고 나머지 줄은 `없음`으로 둔다. 스스로 전체 초기화를 하지 않는다. 리포트의 `## 검증`에 `- ❌ (참고) 문서 초기화가 아직 안 됐다. '문서 초기화'를 요청해야 나머지 코드가 문서에 들어간다`를 적고, `## 인박스 후보`에도 한 줄 올린다.

## 2. 입력 읽기

| 입력 | 어디서 | 읽는 범위 |
| --- | --- | --- |
| 이번 phase가 바꾸려 한 것과 결정 | spec의 설계서와 계획서 | 목표, 결정과 그 이유, 계획서의 Task 목록 |
| 무엇이 검증됐는가 | spec의 끝 검증 리포트 | 결함 표와 `## 검증` |
| 수락 기준 | 백로그 항목(`docs/backlog.md`) | 이번 phase의 항목 줄 |
| 다른 팀이 넘긴 것 | 장부에 적힌 구현 Task의 리포트 | `## 한 일`만 |

리포트는 길잡이로만 쓴다. 문서에 적는 사실의 근거는 코드에서 확인한다.

## 3. 영향 분석

바뀐 경로마다 추적표(`docs/10-traceability/rtm.md`)의 코드 칸과 코드 지도의 모듈 표에 대조한다. 결과를 리포트의 `## 영향 분석` 표에 쓴다.

- 추적표에 닿는 줄이 있다 → 그 요구사항 ID를 따라 SRS, UI 명세, 계약 문서, 테스트 케이스 장부에서 해당 줄을 찾는다.
- 닿는 줄이 없다 → 새 요구사항이나 새 모듈 후보다. 설계서와 백로그 항목에 출처가 있으면 새 줄로 쓰고, 없으면 불일치로 올린다.
- 추적표가 아직 없다 → 대조할 줄이 없다. 바뀐 경로마다 설계서와 백로그 항목에서 출처를 찾아 새 줄로 쓴다.
- 코드 지도가 아직 없다 → 이번 변경 밖에 코드가 없으면(새 프로젝트) 코드 지도를 만든다. 이번 변경 밖에 코드가 이미 있으면(초기화가 안 된 프로젝트) 만들지 않고 `없음`으로 둔다. 그 코드 지도는 초기화가 만든다.
- 고칠 문서가 정해지면 그 문서의 양식만 읽는다.

## 4. 갱신

- 영향 받는 문서의 해당 절만 고친다. 닿지 않는 절은 그대로 둔다.
- 처음 쓰는 문서는 양식의 뼈대에서 시작하고, 근거가 있는 절만 채운다. 근거가 없는 절은 "정해지지 않음"으로 둔다.
- 요구사항은 승인된 설계서와 백로그 수락 기준에 있는 것만 쓴다. 코드를 보고 요구사항을 지어내지 않는다.
- 결정은 ADR 한 건으로 쓰고 출처(설계서 경로와 절, phase 이름)를 적는다.

## 5. 추적표와 기록 맞추기

- 추적표: 이번에 닿은 요구사항 줄의 화면·계약·코드·테스트 칸과 상태를 맞춘다.
- 테스트 케이스 장부: 새 케이스를 더하고, 닿은 케이스의 최근 결과와 phase를 고친다. 결과는 끝 검증 리포트와 최종 테스트에서 가져온다. 테스트를 직접 돌려서 결과를 만들지 않는다.
- 변경 이력: `[Unreleased]`에 사용자가 알아볼 말로 한 줄씩 더한다.
- `wbs.md`: 이번 phase 줄을 더한다.

## 6. 점검

`references/audit.md`의 점검표를 이번에 고친 문서 범위에 돌린다.

## 7. 색인 고치기

- 고친 문서의 줄: 정본 문서, 관련 ID, 마지막으로 갱신한 phase, 상태.
- 쓸 내용이 없는 줄은 `없음`으로 둔다. `해당 없음`은 초기화나 사용자 결정으로만 정한다. 동기화가 정하지 않는다.
- 머리의 "마지막으로 갱신한 phase"는 영향 받는 문서가 없어도 이번 phase로 고친다. 색인을 고친 커밋이 다음 동기화의 기준이 되기 때문이다.

## 8. 리포트

`SKILL.md`의 리포트 형식으로 쓴다. `## 검증`에 적는 줄:

- `grep -c "<phase 이름>" docs/DOCUMENTATION_INDEX.md` → 1 이상
- 점검표에서 이번에 돌린 줄마다 한 줄
- 불일치가 있으면 `- ❌ (참고) 불일치 <N>건: <ID들>`
