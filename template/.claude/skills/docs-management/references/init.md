# 초기화 절차

> 읽는 시점: 작업 단위가 `문서 초기화`일 때. 사용자가 요청할 때만 돈다. 코드가 이미 있는 프로젝트에서 한 번 한다.

doc-steward가 코드·기존 문서·색인을 대조하고 필요한 문서와 지정 작성자를 코디네이터에게 전달한다. 각 문서·절의 첫 작성은 그 담당자가 한다. 이미 근거가 있으면 담당자가 같은 정본에서 갱신한다.

## 읽는 법

- 코드를 통째로 읽지 않는다. 폴더 구조와 진입점부터 보고, 모듈 하나씩 범위를 나눠 읽는다. 큰 파일은 정의와 내보내는 이름을 먼저 찾는다.
- 문서 하나를 쓸 때 그 문서의 양식만 읽는다.
- 기존 문서가 있으면 먼저 목록을 만든다(`README`, `docs/` 아래의 파일, 코드 옆의 문서). 옮기거나 지우지 않는다.

## 순서

양식 이름은 `docs/harness/templates/product-docs/` 기준이다.

| 순서 | 확인할 문서 | 입력 | 양식 |
| --- | --- | --- | --- |
| 1 | 코드 지도 `docs/CODEBASE_MAP.md` | 폴더 구조, 진입점, 모듈 사이의 의존 | `codebase-map.md` |
| 2 | 색인의 "이 폴더 밖의 문서" 표와 기존 문서의 줄 | 기존 문서 목록 | 깔려 있는 색인 |
| 3 | PRD, SRS | 기존 문서, 백로그와 보관 파일, 코드에서 확인되는 기능 | `prd.md`, `srs.md` |
| 4 | UI 명세 | 화면 코드와 라우트 | `ui-spec.md` |
| 5 | 아키텍처 문서, 계약 문서, ADR | 코드 지도, 인터페이스와 스키마 코드, 기존 설계서 | `architecture.md`, `contract.md`, `adr.md` |
| 6 | 테스트 케이스 장부, 런북, 변경 이력 | 테스트 코드, 실행·배포 스크립트, git 기록 | `test-cases.md`, `runbook.md`, `changelog.md` |
| 7 | 추적표, `wbs.md` | 3~6에서 쓴 문서의 ID, `docs/superpowers/`의 설계서와 계획서 목록 | `rtm.md`, `wbs.md` |
| 8 | 점검과 색인 마감 | 쓴 문서 전부 | `references/audit.md` |

## 규칙

- 지정 작성자는 근거가 있는 절을 쓴다. 기존 정본이 있으면 그 경로를 쓴다. 처음 작성한다면 설치 초안을 채워 머리의 `설치 초안` 표시를 지우고 API·DB·ADR·런북은 실제 이름으로 저장한다. doc-steward는 정본과 근거 위치를 확인해 색인에 연결한다.
- 담당이 없으면 배정 상태를 `미배정`으로 기록하고 창구를 통해 지정을 요청한다. 근거가 없는 초안은 보존하고 색인의 정본·최신성 상태를 `없음`으로 둔다. 사용자가 제외한 영역은 `해당 없음`으로 적는다.
- 코드에서 확인한 기능은 상태 `구현됨`으로, 그 기능을 확인하는 테스트가 있으면 `검증됨`으로 적는다. 테스트의 통과 여부를 모르면 `구현됨`에 두고 사유를 적는다.
- 왜 그렇게 만들었는지가 코드와 기존 문서에 없으면 지어내지 않는다. PRD의 목표와 성공 지표, ADR의 맥락처럼 사람의 뜻이 필요한 절은 "정해지지 않음"으로 두고 `## 인박스 후보`에 질문으로 올린다.
- 이미 내려진 결정이 기존 설계서에 있으면 ADR로 옮기고 출처를 적는다. 코드만 보고 추측한 결정은 ADR로 쓰지 않는다.
- 다른 경로의 기존 문서가 같은 내용을 담고 있으면 번호 폴더에 다시 쓰지 않는다. 색인의 정본 문서 칸에 그 경로를 적고, 번호 폴더로 옮길지를 `## 인박스 후보`에 올린다.
- 변경 이력은 지난 git 기록을 전부 옮기지 않는다. 지금 상태를 `[Unreleased]`의 출발점으로 두고, 릴리스 태그가 있으면 태그별 요약만 적는다.

## 리포트

`SKILL.md`의 리포트 형식으로 쓴다. `## 영향 분석` 대신 `## 읽은 범위`(모듈, 읽은 파일 수, 건너뛴 곳과 이유)를 둔다. 마감에 재사용할 근거는 [동기화 절차 4절](sync.md#4-지정-작성자의-반영과-확인)의 `## 반영 확인` 표에 남긴다. `## 검증`에 적는 줄:

- 색인에 `없음`도 `해당 없음`도 아닌 줄마다 정본 파일이 있다
- 점검표의 줄마다 한 줄
- 불일치와 질문이 있으면 `- ❌ (참고) 불일치 <N>건, 질문 <N>건`
