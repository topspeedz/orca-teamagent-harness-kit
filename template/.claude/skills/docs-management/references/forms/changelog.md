# 변경 이력 양식

> 읽는 시점: `docs/12-changelog/CHANGELOG.md`에 변경을 더할 때.

- 바탕 표준: Keep a Changelog.
- 정본 위치: `docs/12-changelog/CHANGELOG.md`. 저장소 루트에 이미 `CHANGELOG.md`가 있으면 그 파일이 정본이다. 새로 만들지 않고 색인에 그 경로를 올린다.
- 이 문서가 정본인 것: 사용자가 알아볼 수 있는 변경의 목록. 릴리스 노트는 따로 쓰지 않는다. 버전 절이 릴리스 노트다.

## 채우는 법

- 사람이 읽는 글이다. 커밋 기록을 옮기지 않는다. 쓰는 사람에게 무엇이 달라졌는지를 한 줄씩 적는다.
- 추가만 하는 기록이다. 이 역할은 `[Unreleased]`에만 더한다. 지난 버전 절은 고치지 않는다.
- 변경은 아래 여섯 종류로 묶는다. 이름은 영어 그대로 쓴다. 해당 줄이 없는 종류의 제목은 쓰지 않는다.

  | 종류 | 담는 것 |
  | --- | --- |
  | `Added` | 새 기능 |
  | `Changed` | 있던 기능의 변경 |
  | `Deprecated` | 곧 없어질 기능 |
  | `Removed` | 없어진 기능. 없앤 요구사항의 ID를 함께 적는다 |
  | `Fixed` | 고친 결함 |
  | `Security` | 보안 취약점과 관련된 변경 |

- 한 줄에 닿는 요구사항 ID를 괄호로 붙인다. 예: `- 할 일을 완료로 표시할 수 있다 (FR-003)`
- 릴리스는 이 역할이 정하지 않는다. 릴리스가 정해졌다는 출처(사용자 결정, 태그)가 있을 때만 `[Unreleased]`의 줄을 새 버전 절로 옮기고 날짜를 적는다.
- 최신 버전이 위다. 날짜는 `<YYYY-MM-DD>` 형식이다. 버전 번호의 규칙은 프로젝트의 것을 따른다.
- 이 문서는 머리 네 줄 대신 아래 뼈대의 머리를 쓴다.

## 뼈대

```markdown
# Changelog

이 프로젝트의 눈에 띄는 변경을 모두 적는다. 형식은 Keep a Changelog를 따른다.

## [Unreleased]

### Added

- <새로 할 수 있게 된 것> (FR-001)

### Changed

- <달라진 것> (FR-002)

### Fixed

- <고친 것>

## [<버전>] - <YYYY-MM-DD>

### Added

- <그 릴리스에 들어간 것>
```
