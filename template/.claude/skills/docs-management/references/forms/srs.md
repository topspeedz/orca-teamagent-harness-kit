# SRS 양식

> 읽는 시점: `docs/02-requirements/srs.md`를 처음 쓰거나 고칠 때.

- 바탕 표준: ISO/IEC/IEEE 29148의 소프트웨어 요구사항 명세 구성.
- 정본 위치: `docs/02-requirements/srs.md`. 시스템이 무엇을 충족해야 하는지를 답한다.
- 이 문서가 정본인 것: 요구사항 문장과 수용 기준. 요구사항의 상태와 테스트 연결은 추적표가 정본이다.

## 채우는 법

- 요구사항 한 줄은 한 문장이고 하나만 말한다: "시스템은 <조건>일 때 <무엇>을 해야 한다."
- 수용 기준은 검증자가 그대로 검사할 수 있게 쓴다. 대상, 조건, 기대 결과가 들어간다. 끝난 백로그 항목의 수락 기준을 옮겨 온다.
- 기능 요구사항은 `FR-###`, 그 밖의 요구사항(3.2~3.7)은 `NFR-###`이다.
- 출처 칸에는 PRD의 `US` ID를 적는다. 사용자 스토리가 없으면 설계서 경로를 적는다.
- 우선순위는 출처에 있을 때만 적는다. 없으면 `정해지지 않음`이라고 쓴다.
- 검증 방법은 `시험`, `시연`, `검사`, `분석` 중 하나다.
- 인터페이스와 데이터의 형식은 여기에 쓰지 않는다. 계약 ID(`API-###`, `DATA-###`)로 가리킨다.
- 줄마다 아래 성질을 본다. 어긋나는 줄은 고치지 않고 `(확인 필요: 사유)`를 붙여 올린다. 문장을 바꾸는 것은 요구사항을 정하는 일이기 때문이다.
  - 필요하다 · 구현 방법에 매이지 않는다 · 모호하지 않다 · 완전하다 · 하나만 말한다 · 실현할 수 있다 · 검증할 수 있다 · 옳다 · 규칙에 맞는다
- 아직 코드에 없는 요구사항은 줄 끝에 `(계획됨)`을 붙인다. 상태 칸은 두지 않는다.
