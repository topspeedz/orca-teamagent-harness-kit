# 요구사항 추적표(RTM) 양식

> 읽는 시점: `docs/10-traceability/rtm.md`를 처음 쓰거나 고칠 때. 동기화의 영향 분석에서 바뀐 코드가 어느 요구사항에 닿는지 찾을 때.

- 바탕 표준: 추적표(RTM) 관행. 요구사항에서 테스트로(정방향), 테스트에서 요구사항으로(역방향) 따라갈 수 있게 한다.
- 정본 위치: `docs/10-traceability/rtm.md`. 30KB를 넘으면 영역별로 나눈다.
- 이 문서가 정본인 것: 요구사항과 화면 기능·계약·코드·테스트의 연결, 요구사항의 상태. 다른 문서는 연결 표를 따로 만들지 않는다.

## 채우는 법

- SRS의 요구사항마다 한 줄이다. SRS에 있는데 여기 없는 요구사항이 있으면 안 된다.
- 요구사항 칸에는 문장을 옮기지 않는다. 알아볼 수 있는 짧은 이름만 적는다. 문장은 SRS가 갖는다.
- 코드 칸에는 그 요구사항을 구현한 파일 경로를 적는다. 여럿이면 쉼표로 잇는다. 동기화의 영향 분석이 이 칸으로 바뀐 파일을 찾으므로 경로를 정확히 적는다.
- 상태는 근거로 정한다.
  - 코드 칸이 비었다 → `계획됨`
  - 코드 칸이 있고 테스트 칸이 비었거나 최근 결과가 통과가 아니다 → `구현됨`
  - 테스트 칸이 있고 테스트 케이스 장부의 최근 결과가 통과다 → `검증됨`
  - 문서와 코드가 다르거나 근거를 찾지 못했다 → `확인 필요`. 비고에 사유를 적는다
- 빈칸을 다른 값으로 메우지 않는다. 빈칸은 빈칸 요약에 세고, 점검에서 올린다.
