# 데이터·인터페이스 계약 양식

> 읽는 시점: `docs/05-api/`나 `docs/06-database/`의 계약 문서를 처음 쓰거나 고칠 때.

- 바탕 표준: Open Data Contract Standard의 절 구성(기본 정보, 스키마, 참조, 품질, 서비스 수준, 서버, 지원, 역할). 인터페이스 계약에는 연산과 오류 코드를 더했다.
- 정본 위치: 인터페이스는 `docs/05-api/<인터페이스 이름>.md`, 데이터는 `docs/06-database/<데이터 묶음 이름>.md`. 계약 하나에 파일 하나다.
- 이 문서가 정본인 것: 요청과 응답의 형식, 스키마, 오류 코드. 기계가 검증하는 파일이 있으면 그 파일이 정본이고 이 문서는 요약하고 가리킨다.

## 채우는 법

- 계약 ID는 인터페이스가 `API-###`, 데이터가 `DATA-###`이다.
- 뼈대의 스키마 절은 둘이다. 인터페이스 계약이면 "스키마: 연산"을, 데이터 계약이면 "스키마: 객체"를 쓰고 다른 쪽은 지운다.
- 기계가 검증하는 파일(OpenAPI YAML, SQL 스키마, 마이그레이션, 타입 정의)이 있으면 필드 표를 통째로 옮기지 않는다. 그 파일의 경로를 적고, 이 문서에는 연산이나 객체의 목록과 뜻만 둔다.
- 필드와 오류 코드는 코드에서 확인한 것만 적는다. 근거 경로를 계약마다 적는다.
- 서비스 수준은 정해진 것만 적는다. 정한 적이 없으면 "정해지지 않음"이다. 지어내지 않는다.
- 비밀값(키, 비밀번호, 토큰)과 운영 주소의 인증 정보는 적지 않는다. 환경 변수의 이름만 적는다.
- 계약 상태는 계약의 수명을 말한다: `proposed`, `draft`, `active`, `deprecated`, `retired`. 추적표의 요구사항 상태와 다른 값이다.
