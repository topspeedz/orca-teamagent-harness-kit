# PRD 양식

> 읽는 시점: `docs/01-product/prd.md`를 처음 쓰거나 고칠 때.

- 바탕 표준: Atlassian 제품 요구사항 양식.
- 정본 위치: `docs/01-product/prd.md`. 무엇을 왜 만드는지를 답한다.
- 이 문서가 정본인 것: 목표, 성공 지표, 가정, 사용자 스토리, 하지 않는 것. 요구사항 문장과 수용 기준은 SRS가 정본이다. 여기서는 `FR` ID만 가리킨다.

## 채우는 법

- 목표, 성공 지표, 가정은 승인된 설계서와 사용자 결정에 있는 것만 적는다. 없으면 "정해지지 않음"으로 두고 열린 질문에 올린다. 지어내지 않는다.
- 사용자 스토리는 한 문장이다: "<누구>로서 <무엇>을 하고 싶다. <왜>." ID는 `US-###`이다.
- 중요도는 `필수`, `중요`, `있으면 좋음` 중 하나다. 출처에 없으면 비워 둔다.
- 화면 그림을 붙이지 않는다. 화면 ID로 UI 명세를 가리킨다.
- 열린 질문에 답이 나면 답과 답한 날을 적고, 그 답이 닿는 절을 함께 고친다.

## 뼈대

```markdown

- 읽는 시점: 무엇을 왜 만드는지 확인할 때. 새 기능의 범위를 정하기 전.
- 역할과 소유 범위: 제품의 목표, 성공 지표, 사용자 스토리, 하지 않는 것. 요구사항 문장은 `docs/02-requirements/srs.md`가 갖는다.
- 소유 에이전트: `doc-steward`
- 마지막으로 갱신한 phase: <phase>

| 항목 | 값 |
| --- | --- |
| 문서 상태 | <초안 / 검토 중 / 확정> |
| 대상 릴리스 | <버전 또는 "정해지지 않음"> |
| 문서 소유 | <제품을 책임지는 사람> |
| 관련 문서 | <SRS, UI 명세, 설계서의 경로> |

## 목표
```
