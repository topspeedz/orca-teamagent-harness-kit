# 우선순위와 묶음

> 읽는 시점: `product-manager`가 항목에 우선순위를 붙이고 묶음을 제안할 때. `prd-writer`는 "세 등급" 절만 읽는다.

- 바탕: revfactory/harness-100의 46-product-manager(Apache-2.0)에서 rice-prioritizer와 sprint-planner의 방법을 가져와 이 틀의 규칙에 맞게 다시 썼다.

## 세 등급

| 값 | 뜻 |
| --- | --- |
| `필수` | 없으면 이 phase의 목표를 이룰 수 없다 |
| `중요` | 중요하지만 다른 방법으로 돌아갈 수 있다 |
| `있으면 좋음` | 없어도 된다 |

- 하지 않기로 한 것은 등급을 붙이지 않고 PRD의 `## 하지 않는 것`에 간다.
- 등급은 브리프의 사용자 결정에 근거가 있을 때만 적는다. 없으면 백로그 비고에 `우선순위 정해지지 않음`으로 적고 추천값을 `## 사용자 결정 필요`에 올린다. 확정되면 그 값으로 바꾼다.

## 순서

등급이 먼저다. 같은 등급 안에서는 RICE 점수가 있으면 점수 순, 없으면 다른 항목이 기대는 항목이 먼저다.

## RICE

```
RICE = (Reach × Impact × Confidence) ÷ Effort
```

| 값 | 뜻 | 누가 정하는가 |
| --- | --- | --- |
| Reach | 한 분기에 이 항목이 닿는 사용자나 사건의 수 | 사용자가 준 숫자만 쓴다. 에이전트가 추정하지 않는다 |
| Impact | 사용자 한 명에게 닿는 크기. 3 아주 큼, 2 큼, 1 보통, 0.5 작음, 0.25 아주 작음 | `product-manager`가 추천하고 사용자가 확정한다 |
| Confidence | Reach와 Impact를 믿는 정도. 100% 측정한 자료, 80% 설문이나 인터뷰, 50% 감, 20% 가설 | `product-manager`가 추천하고 사용자가 확정한다 |
| Effort | 사람 월 대신 [decomposition.md](decomposition.md)의 복잡도 값 | 자동 |

- Reach가 없는 항목은 점수를 계산하지 않고 등급만 쓴다.
- Impact는 사용자가 말한 중요도의 근거로, Confidence는 사용자가 준 근거의 종류로 고른다. 고른 이유를 함께 적는다.
- **추천값은 백로그에 쓰지 않는다. 사용자가 확정한 값만 적는다.** 추천은 리포트의 `## 사용자 결정 필요`에 항목마다 한 줄로 올린다. 창구가 묶음 승인 전에 묻고, 답을 브리프에 더한 뒤 이 일을 새로 띄운다. 그때 확정된 값으로 점수, 순서, 묶음 제안을 다시 쓴다. 묶음 승인은 그다음에 묻는다.
- 사용자가 확정한 Confidence가 50% 이하인 항목은 조사 항목을 먼저 둔다. 추천값에는 이 규칙을 걸지 않는다.
- 백로그 비고의 표기: `RICE <점수>(R n · I n · C n%)`.

## 묶음 제안

리포트의 `## 묶음 제안`에 세 묶음으로 적는다.

| 묶음 | 담는 것 |
| --- | --- |
| 이번 | 이 phase에서 만들 항목 |
| 다음 | 다음 phase의 후보 |
| 나중 | 그 뒤 |

- 이번 묶음은 순서대로 담는다. 서로 기대는 항목은 같이 넣거나 앞선 것을 먼저 넣는다. 불확실성이 큰 항목은 조사 항목을 이번에 넣는다. 그 항목이 `필수`면 본 항목을 이번에 함께 넣을지 `## 사용자 결정 필요`에 올려 묶음 승인 때 사용자가 정한다.
- 묶음마다 항목 표(BL, 한 줄, 우선순위, 복잡도)를 둔다. 창구는 이 절만 읽고 승인 질문을 만든다.
- 목표 한 문장을 적는다: "이 phase가 끝나면 <무엇>이 된다." 묶음이 끝났을 때 동작하는 결과가 하나 있어야 한다.
- 이번 묶음의 항목 수와 복잡도 합을 적는다.
- 지난 실적: `docs/backlog-archive.md`에서 최근 세 phase가 끝낸 항목의 복잡도 합을 구해 적는다(보관된 항목의 비고에 phase 이름이 근거로 남아 있다). 없으면 "실적 없음".
- 이번 묶음의 복잡도 합이 지난 실적 평균의 80%를 넘으면 그 사실을 적는다. 막지는 않는다.
- 자르는 선은 사용자가 정한다. 저장되는 것은 승인된 이번 묶음뿐이다(브리프의 `## 백로그 항목`). 다음과 나중은 백로그의 우선순위로만 남는다.
