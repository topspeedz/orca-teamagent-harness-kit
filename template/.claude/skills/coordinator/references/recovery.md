# 압축에서 돌아왔을 때

> 읽는 시점: 코디네이터의 대화가 압축된 직후. 압축 요약만 믿고 이어 가지 않는다.

압축 요약에는 Run ID, 진행 중인 Dispatch ID, 추적 중인 대기 작업, 현재 단계, 사용자 결정 원문이 남아 있어야 한다(공통 지침의 `## Compact Instructions`). 그래도 아래 순서로 다시 맞춘다.

1. **장부와 브리프를 다시 읽는다.** `_workspace/_run/<phase>/ledger.md`와 `brief.md`다. 기억이 아니라 장부의 상태로 이어 간다.
2. **추적을 잃은 대기를 먼저 멈춘다.** 하네스가 추적하는 백그라운드 작업 목록을 보고, 지금 기억에 없는 `check --wait`는 멈춘다. 한 Run에 대기는 동시에 하나다. 앞 대기를 남긴 채 새 대기를 걸면 같은 묶음을 두 대기가 나눠 가진다.
3. **상태를 본다.** 메시지를 소비하지 않는 명령으로 본다.

   ```text
   node .claude/scripts/orca-launch.mjs snapshot --run <id>
   ```

   대기 중인 메시지와 워커 목록을 장부와 대조한다. 장부에 없는 `worker_done`이 있으면 다음 대기에서 받아 정산한다. 이미 장부에 정산된 message id는 다시 정산하지 않는다.
4. **대기를 다시 건다.** `SKILL.md`의 대기 계약대로 백그라운드 대기 하나를 건다.

- 침묵, 타임아웃, 목록 부재만으로 워커를 종료로 판정하거나 다시 띄우지 않는다.
- 스윔레인은 장부의 상태로 같은 파일 경로에 다시 게시한다.
