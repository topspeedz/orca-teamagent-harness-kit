# DAG 스윔레인

작업 DAG를 **레인 = 팀, 열 = 시간 순 슬롯** 표로 그린다. 같은 열 = 실제로 동시에 도는 노드(병렬), 레인 안 한 행 = 워커 한 명. 슬롯 폭은 소요 시간에 비례하지 않는다. 형식의 정본은 [assets/reference.html](assets/reference.html) — [examples/reference.json](examples/reference.json)을
`scripts/render.mjs`로 렌더한 결과이고, 렌더러는 이 파일의 첫 `<style>`을 CSS로 읽는다.
규칙이나 렌더러를 바꾸면 `reference.json`을 다시 렌더해 기준 파일을 갱신한다 — 둘이 다르면 기준 파일이 낡은 것이다.

## 언제

| 때 | 하는 일 |
|---|---|
| 설계 승인 전 | 팀 단위 흐름과 사람 승인 지점을 모두 대기로 표시 |
| 실행 승인 전 | Task ID·BL·선행 의존·배정을 대조하고 모든 Task를 `wait`로 게시. 같은 버전의 T+ 워터폴을 함께 제시 |
| 실행 중 단계 전환(웨이브 시작·끝, 검증 진입, 수정 루프) | 장부 상태로 `status`만 바꿔 재렌더·재게시 |
| 팀 리더 통합 보고를 받았을 때 | 그 팀 노드 상태와 "지금" 메모 갱신 |
| 사용자가 DAG·진행 상황을 그려 달라고 할 때 | 위와 같은 절차 |

하네스 실행 중에는 같은 phase의 `orca-tasks.json`에서 계획 ID와 실제 Task ID를 연결하고, `orca-launch.mjs ready --map <map>`의 상태와 장부의 게이트·팀원 보고를 대조한다. 새로 게시할 진행 사본의 상태만 갱신한다. 승인 파일과 검토 당시 DAG는 보존한다.

## 절차

1. 입력 JSON을 쓴다(아래 형식, 예시 [examples/reference.json](examples/reference.json)). Run 작업 폴더에 둔다(예: `_workspace/<run>/dag.json`).
2. 프로젝트 번들은 `node .claude/skills/dag-swimlane/scripts/render.mjs <dag.json> <dag.html>`로 렌더한다. 전역판을 선택한 프로젝트는 해당 스킬의 같은 스크립트를 사용한다 — 실패하면 exit 1과 이유(어느 연결선이 어느 노드를 지나는지 등). 연결선이 노드를 지나면 `row`·`col`을 옮겨 출발 행이나 도착 행을 비우고 다시 돌린다. 겹친 채로 게시하지 않는다.
3. Artifact 도구로 `<dag.html>`을 게시한다(첫 게시 `icon: "chart"`). 갱신은 **같은 파일 경로로 재게시** = 같은 URL. 새 경로는 새 URL이 되니 경로를 바꾸지 않는다. 출력은 Artifact 페이지 계약(2~4단어 `<title>`, `:root` 토큰, 다크 두 경로, `body` 배경, 16px 거터)을 이미 지킨다.
4. 게시·갱신 권한이 코디네이터에게만 있는 하네스(워커는 게시하지 않음)면 워커는 JSON·HTML까지만 만들고 경로를 보고한다.

## 입력 형식

```jsonc
{
  "title": "탭 제목 2~4단어", "heading": "h1 (생략 시 title)",
  "sub": "부제 — 신뢰 HTML(<b> 등)", "aria": "그림 요약 한 문장 (생략 시 열 순서로 자동)",
  "columns": ["t0 · 계획", "t1", ...],                 // X축 = 시간 순 슬롯. 열이 늘면 폭이 는다(250px/열)
  "lanes": [{ "id": "dev", "name": "개발 팀", "roles": ["역할 이름", "· 보조 줄"], "tone": "dev" }],
  "nodes": [{ "id": "t1", "lane": "dev", "col": 1, "row": 0,
              "bl": "BL-0012", "title": "번호·Task", "sub": "회색 보조 줄", "status": "done|run|wait", "write": true,
              "agent": "claude|codex", "model": "opus", "effort": "low|medium|high|xhigh|max",
              "conditional": true, "afterFix": "<사유>" }],      // 선택: 계획 검토가 읽는다
  "groups": [{ "id": "verify-all", "nodes": ["dr", "cr", "qa"] }],   // 병렬 검증 묶음 → 점선 상자, 연결의 끝점이 될 수 있다
  "edges": [{ "from": "t1", "to": "t2", "label": "High 이상", "loop": true, "merge": true }],
  "notes": [{ "title": "신뢰 HTML", "body": "신뢰 HTML" }]          // 3~4개,
  "rounds": [{ "n": 1, "title": "중간", "verify": ["q3", "r1"], "fix": "f1", "recheck": "q8", "note": "글" }]  // 선택: 검증→수정 회차
}
```

- `tone`: `plan`·`dev`·`verify`·`coord`·`harness` 중 하나(기준 파일의 색 토큰). 생략하면 순서대로. **`harness` 레인 1개 필수** — 회고·하네스 Task가 어디서 도는지 보이게.
- `row`: 레인 안의 워커 행(80px 간격) — 같은 워커의 노드는 같은 `row`. 생략하면 입력 순서로 0, 1, 2…. 소수(0.5)로 이웃 열과 높이를 맞춘다. 레인 높이는 자동.
- `bl`: 백로그 번호. BL이 발급된 Run이면 모든 노드에 넣는다(계획서 `## DAG`의 그 Task의 `백로그:` 줄로 대조). 아래 규칙 **노드 라벨** 참고.
- `sub`(2번째 줄) = **작업 내용**(backlog 제목에서 Task ID를 뺀 것). 역할·등급·플랫폼·BL 번호를 넣지 않는다 — 각각 레인·아이콘·라벨이 보여 준다. 제목·작업 내용은 카드 너비를 넘으면 말줄임표로 표시한다. 마우스를 올리면 두 줄의 전문이 여러 줄로 펼쳐진다. 카드를 클릭하거나 키보드로 Enter·Space를 누르면 노드의 전체 입력값, 현재 모델 선택과 연결 관계가 열린다. Esc 또는 닫기로 돌아온다.
- 노드 상세의 실행 시간은 입력 DAG와 같은 폴더의 `actual.json`에서 Task ID가 일치하는 `start`·`end`의 차이를 표시한다. 진행 중이면 기록된 시작부터 그림 생성 시점까지의 경과를 표시한다. 시작 전이나 실측 기록이 없는 경우에는 그 상태를 표시한다.
- 실행 승인용 DAG는 각 워커 노드에 `role`(역할명)·`unit`(작업 단위)·`bl`을 적는다. `agent`는 런타임이다. effort가 없는 배정은 null을 쓴다. 팀장에게 허용한 내부 분해의 역할·단위·런타임·모델·effort는 부모 노드의 `members`에 같은 필드명으로 명시하고 승인 화면에도 싣는다. 사람 승인 노드는 `kind: "approval"`로, 워커 없는 이정표는 `kind: "milestone"`으로 표시하고 배정 필드를 생략한다. 각 실행 BL은 `BL-####` 형식이며 복수이면 배열 또는 쉼표로 나열한다. `edges`는 선행 입력, `loop`는 재검 경로다.
- `agent`·`model`·`effort`: 카드 아래 테두리 오른쪽에 걸친 아이콘 태그(✳ Claude / ◎ Codex + effort 작은 글씨 L/M/H/XH/MAX). 모델명은 툴팁. gate처럼 워커가 없으면 생략.
- `members`(팀원)는 그림 아래 칸이 아니라 카드 미리보기의 `팀원` 목록(`id`·역할/단위 — `agent model/effort`, 완료가 아니면 상태)으로 보인다. 아래 **팀 내부 배정** 칸은 `choices`로 팀원 선택 칸을 그릴 때만 나온다.
- `rounds`(선택): 검증 → 수정(→ 재검) 회차. `verify`·`fix`·`recheck`는 노드 id 하나 또는 배열, `n`은 1부터. 렌더러가 라벨 없는 해당 연결에 `수정 N회차`·`재검 N회차`를 붙이고, 수정·재검 카드 왼쪽 아래에 `N회차` 태그를 그리고, 카드에 마우스를 올리면 펼쳐지는 미리보기에 그 카드의 회차 역할(`N회차 검증·수정·재검`)과 `agent model/effort`를 적는다. 수정 카드에는 `note`와, 회차가 둘 이상이면 수정 배정이 회차마다 같았는지 비교한 줄을 더한다. 팀원 배정은 승인 값이 아니라 실제 기동 값(spec의 `배정:` 줄이나 기동 영수증)을 넣는다. 없는 노드 id면 exit 1. 하네스 실행 중이면 수정 루프가 돌 때마다 회차를 더해 재게시한다.
- `rounds`는 계획 검토(`orca-launch.mjs review`)도 읽어 검증·수정·재검 Task를 가른다. 노드 id는 모든 회차를 통틀어 한 번만 나오고, `n`은 정수다. 두 번째 회차의 `verify`는 첫 회차의 재검 Task다.
- `conditional: true`(선택): 조건이 맞지 않으면 워커를 띄우지 않고 `orca-launch.mjs skip`으로 닫을 수 있는 노드다. 검증 Task에는 두지 않고, 계획 검토가 거부한다.
- `afterFix: "<사유>"`(선택): 수정 Task 뒤에 두는 검증 노드다. 계획 검토는 이 필드가 없는 검증 Task가 수정 Task 뒤에 있으면 거부한다. 다른 Task를 거쳐 뒤에 있어도 같다. 재검 Task는 이 필드 없이 수정 Task 뒤에 둘 수 있다. 이 노드는 띄울 때 `결함 ID:`와 `수정 diff:` 없이 통과한다. 사유는 빈 문자열이 아니어야 한다. 수정 노드에 두면 그 노드를 수정 사슬 2단의 셈에서 뺀다(사용자가 승인한 회차). 그 노드도 수정 Task의 기동 규칙대로 띄운다.
- `write: true`: 외부 데이터(운영 DB·커머스 API 등)를 쓰는 Task. 경고색 굵은 테두리 + 보조 줄 경고색. 메모 카드 하나를 범례로 쓴다(`<span class="key"></span>`).
- `loop: true`: 앞 열로 되돌아가는 연결(재검 등) — 점선, 출발 노드 아래(또는 위) 가운데에서 내려가 대상 오른쪽으로 들어간다.
- `merge: true`: 멀리서 합류하는 연결 — 출발 행을 따라 대상 열 가운데까지 간 뒤 대상 위(또는 아래)로 들어간다.
- 텍스트(`title`·`sub`·레인·열·라벨)는 이스케이프하고 `sub`(부제)·`notes`만 HTML로 넣는다. 사용자·외부 입력을 그 두 필드에 그대로 넣지 않는다.

- `choices`(선택): 계획 승인 때 사용자가 워커마다 배정을 고르게 한다. 워커 노드 카드 아래에 복잡도 줄(`복잡도 5 (기술 · 도메인 · 불확실성)`, 없으면 `BL 없음 · 모델 표 값`), Claude model/effort `<select>` 하나(모델별 `<optgroup>`, 모든 조합), `codex` 체크박스, 근거 줄(`추천 <값>: <why>`)을 그린다. 기준값 선택지 끝에 `(기준값)`, 추천값에 `(추천)`, 둘이 같으면 `(기준값·추천)`. 처음 선택은 `base`(생략하면 노드의 `model/effort` — codex 노드는 Claude 값의 `base`가 필요하다), 체크박스 처음 상태는 `agent`가 `codex`인지. 체크하면 옆에 `→ <치환 값>`. 기준값과 다른 카드는 노란 바탕이 되고 그림 위 "기준값과 다른 Task" 목록에 든다. `fixed: true` 노드는 값과 `(고정)`만 보인다. 고를 수 있는 노드에 `recommended`·`why`가 없으면 exit 1. 열·행 간격이 선택 칸만큼 늘고 연결선 검사도 선택 칸을 피한다.
- 선택 저장: 페이지가 Artifact `db` 기능(`await claude.use("db")`)으로 바뀔 때만 `choices/<노드 id>` 문서에 `{model, effort, codex, at}`(Claude 값, `at`은 ms 시각)를 한 번 쓴다. 로드할 때는 쓰지 않고, 저장된 값이 있으면 그 값으로 그린다. db가 없으면 저장되지 않는다고 안내하고 화면에서만 선택을 바꿀 수 있다. 렌더러는 HTML만 만들고, 게시하는 쪽이 `capabilities: {db: {}}`로 게시한다. 저장된 선택은 `ArtifactData`의 `list`(`collection: "choices"`)로 읽는다.

### v2 실행 승인

- 최상위에 `routingVersion: 2`와 프로젝트 모델 표에서 얻은 `choices`를 둔다. 각 실행 노드와 팀원의 `routing`에 `model-routing.mjs`의 평가 결과를 그대로 넣는다. `fixed: true`인 고정 역할은 배정만 표시한다. 사람 승인과 이정표는 배정이 없다.
- 카드는 최종 C/U/R/V/F, E, Haiku 분류 상태, Claude 기준 추천, 현재 런타임 조합을 보여 준다. 카드 상세에서 각 축의 계획 점수와 근거, 대안과 판정 후 점수, Haiku 사유, 모델 판정 조건, E 계산식을 확인한다. 팀원별 선택과 근거는 그림 아래 **팀 내부 배정**에 있다.
- **추천 사용 · 기동 직전 재평가**를 고르면 `routing.mode: "auto"`다. **직접 지정** 아래에서 조합을 고르면 추천과 같은 조합도 `"manual"`로 고정한다. Codex를 체크하면 해당 프로젝트 치환표의 실제 모델·effort를 즉시 표시한다. 예를 들어 기본표의 Fable/max는 Codex에서 Astra/ultra다. 런타임은 승인한 값으로 고정한다.
- 선택 변경 시 DB 문서에 `{model, effort, codex, mode, at, drawing}`을 쓴다. `model/effort`는 Claude 기준값이다. `drawing`은 입력 DAG를 `JSON.stringify`한 UTF-8 문자열의 SHA-256 해시다. 같은 DAG를 다시 열면 해당 그림의 선택만 복원하고, 그림이 바뀌면 새 DAG의 모드와 배정에서 시작한다. 팀원 키는 부모 Task ID·역할·작업 단위를 각각 URL 인코딩하고 각 요소 안의 `~`도 `%7E`로 바꾼 뒤 `~`로 연결한다. 팀원 문서에는 `parentId, role, unit`도 저장한다.
- **선택 파일 저장**은 현재 그림에서 설정한 항목을 `routing-choices.json`에 `[{id,data}]`로 내보낸다. 추천값 직접 고정과 자동 재평가로 되돌린 선택도 들어간다. 로컬 HTML에서는 창을 닫기 전에 이 파일을 저장한다. DB를 사용하는 Artifact에서는 `ArtifactData list choices`로 같은 선택을 읽을 수 있다.
- 창구는 선택 파일 또는 DB 결과를 `dag-routing-choices.mjs`로 반영해 노드·팀원 각각의 `routing.mode`, `base`(선택한 Claude 조합), `agent/model/effort`를 검토할 DAG에 기록한다. `recommended`는 평가 결과의 `routing.claude`다. Codex 체크 변경 시 같은 점수를 승인할 런타임으로 치환해 평가 결과에도 반영한다. 사용자가 이 최종 배정과 위임 범위를 승인한 뒤 실행한다.

## 규칙 (기준 파일에서 추출)

- **캔버스:** 고정 px SVG + `.scroll` 가로 스크롤. 축소해서 화면에 맞추지 않는다. mermaid 같은 자동 맞춤 렌더는 쓰지 않는다.
- **Y = 팀 레인:** 팀별 색 띠, 굵은 팀 이름 + 역할 mono 보조 줄. 하네스 레인 필수.
- **X = 시간 순 슬롯:** 열 머리는 `t0`, `t1 · 웨이브 0`처럼 슬롯 번호(+ 필요하면 단계 이름), 열 사이 점선. 단계·주제별로 열을 나누지 않는다. 열 배치 규칙:
  - 같은 열 = 그 시점에 실제로 동시에 진행되는 노드. 팀이 달라도 같은 시점이면 같은 열.
  - 레인 안 `row` 하나 = 워커(또는 리더) 한 명. 한 워커가 차례로 하는 노드는 같은 행의 연속된 열에 놓는다 — 한 워커의 노드 둘이 같은 열에 오면 안 된다. 레인 `roles`에 행별 워커를 적는다(예: "행0 engineer 미러 체인 · 행1 curator 묶음").
  - 노드의 열 = max(선행 노드의 열 + 1, 같은 워커 직전 노드의 열 + 1). 사용자 승인처럼 대기가 끼면 그 대기도 한 슬롯을 차지하는 노드로 둔다.
  - 한 Task가 두 워커로 나뉘면(예: 스킬 부분 · 문서 부분) 노드도 나눈다.
  - 메모 카드 하나는 "읽는 법"(열 = 시간 순, 행 = 워커)으로 쓴다.
- **노드 = 2줄 카드**(190×56): 굵은 제목(번호·Task) + 회색 보조 줄, 상태 텍스트·BL 번호는 아래 노드 라벨. 테두리 = 레인 색, 완료 2.5 + **녹색 테두리**(`--done`, 레인 색 대신 — 쓰기 Task도 테두리는 녹색, 보조 줄 경고색은 유지) · 진행 3 · 대기 점선 + 흐림. 팀 색에는 녹색을 쓰지 않는다(완료와 겹침).
- **노드 라벨**: BL 번호 = 카드 **왼쪽 위 모서리**에 걸친 **사선(-35°)** 태그(60×16, 11px, 레인 색 바탕). 상태는 라벨이 아니라 카드 안 오른쪽 위 **텍스트**(`✓ 완료` 녹색 / `▶ 진행` / `대기` 회색, 13px). 카드 폭 190·2줄 내용은 바꾸지 않는다 — BL을 제목에 붙이거나 카드를 넓히지 않는다. 상태를 라벨로 만들지 않는다.
- **범례:** 렌더러가 부제 아래에 자동으로 그린다 — 쓰인 tone마다 색 견본 + 뜻(`TONE_MEANING`: plan 기획 · dev 제작 · verify 검증 · coord 조정 · harness 하네스) + 그 tone의 레인 이름, 그리고 완료·진행·대기 표시. 레인 `tone`은 이 뜻에 맞춰 고른다(예: 디자인·3D 제작 레인 = `dev`). 한 줄 노드는 쓰지 않는다.
- **쓰기 Task:** 경고색 굵은 테두리 + 보조 줄 경고색.
- **병렬 검증 묶음:** 점선 그룹 상자. 묶음 전체로 나가고 들어오는 연결은 상자 변에 고르게 나눈 점을 쓴다.
- **연결점:** 노드마다 출력점은 오른쪽 가운데 1개, 입력점은 왼쪽 가운데 1개(합류·루프 예외는 위 형식 절).
- **연결선:** 인접 열 = S자 곡선(열 사이 틈 가운데에서 꺾임). 먼 연결 = 출발 행 또는 도착 행을 따라 최단 직각(빈 행이어야 한다). 어떤 연결선도 노드 사각형을 지나지 않는다 — 렌더러가 검사하고 exit 1. 되돌아가는 루프는 점선. 조건이 있는 연결에는 라벨(High 이상·재검·합류 등).
- **메모 카드 3~4개**(그림 아래): 병렬 설명 · 쓰기 범례 · 지금 상태 · 주의.
- **글자:** 레인·제목·보조 줄·라벨 ≥14px. 기준 파일 그대로 상태·부제 `code`만 13px, BL 태그만 11px.
- **테마:** `:root` 토큰 + `prefers-color-scheme: dark`(`:root:not([data-theme="light"])`) + `:root[data-theme="dark"]` 둘 다.

## 검사

```bash
node ~/.claude/skills/dag-swimlane/scripts/render.mjs --self-test
```
`examples/reference.json`이 기준 파일과 같은 수(레인 5·열 9·노드 16·연결 20·그룹 1)로 렌더되고,
`examples/crossing.json`(먼 연결이 노드를 지나는 입력)이 거부되는지 본다. 렌더러를 고치면 이 명령과
브라우저 1회 비교(기준 파일과 나란히, 로컬 http 서버 — `file://`이 막힌 브라우저 도구가 있다)를 다시 한다.

렌더러가 검사하지 않는 것: 연결선끼리의 겹침(두 먼 연결이 같은 열 경계를 쓰면 포개진다 — 한쪽에 `merge`), 라벨-노드 겹침.
먼 연결은 출발 행·도착 행 두 후보만 보고 우회하지 않는다. 둘 다 막히면 exit 1이니 행을 옮긴다.

## 하지 않는 것

- 좌표를 손으로 쓴 SVG를 새로 만들지 않는다 — JSON을 고치고 다시 렌더한다.
- 상태를 다이어그램에만 적지 않는다. 장부가 정본, 그림은 그 사본이다.
- 매 heartbeat마다 재게시하지 않는다. 단계 전환·리더 보고·사용자 요청 때만.
