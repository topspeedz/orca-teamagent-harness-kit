# DAG 스윔레인

작업 DAG를 **레인 = 팀, 열 = 시간 순 슬롯** 표로 그린다. 같은 열 = 실제로 동시에 도는 노드(병렬), 레인 안 한 행 = 워커 한 명. 슬롯 폭은 소요 시간에 비례하지 않는다. 형식의 정본은 [assets/reference.html](assets/reference.html) — [examples/reference.json](examples/reference.json)을
`scripts/render.mjs`로 렌더한 결과이고, 렌더러는 이 파일의 첫 `<style>`을 CSS로 읽는다.
규칙이나 렌더러를 바꾸면 `reference.json`을 다시 렌더해 기준 파일을 갱신한다 — 둘이 다르면 기준 파일이 낡은 것이다.

## 언제

| 때 | 하는 일 |
|---|---|
| 계획 승인 직후 | 모든 Task를 `wait`로 첫 게시 |
| 실행 중 단계 전환(웨이브 시작·끝, 검증 진입, 수정 루프) | 장부 상태로 `status`만 바꿔 재렌더·재게시 |
| 팀 리더 통합 보고를 받았을 때 | 그 팀 노드 상태와 "지금" 메모 갱신 |
| 사용자가 DAG·진행 상황을 그려 달라고 할 때 | 위와 같은 절차 |

상태의 출처는 프로젝트의 Task 장부(예: `_workspace/<run>/00_ledger.md`)다. 기억으로 상태를 적지 않는다.

## 절차

1. 입력 JSON을 쓴다(아래 형식, 예시 [examples/reference.json](examples/reference.json)). Run 작업 폴더에 둔다(예: `_workspace/<run>/dag.json`).
2. `node ~/.claude/skills/dag-swimlane/scripts/render.mjs <dag.json> <dag.html>` — 실패하면 exit 1과 이유(어느 연결선이 어느 노드를 지나는지 등). 연결선이 노드를 지나면 `row`·`col`을 옮겨 출발 행이나 도착 행을 비우고 다시 돌린다. 겹친 채로 게시하지 않는다.
3. Artifact 도구로 `<dag.html>`을 게시한다(첫 게시 `icon: "chart"`). 갱신은 **같은 파일 경로로 재게시** = 같은 URL. 새 경로는 새 URL이 되니 경로를 바꾸지 않는다. 출력은 Artifact 페이지 계약(2~4단어 `<title>`, `:root` 토큰, 다크 두 경로, `body` 배경, 16px 거터)을 이미 지킨다.
4. 게시·갱신 권한이 코디네이터에게만 있는 하네스(워커는 게시하지 않음)면 워커는 JSON·HTML까지만 만들고 경로를 보고한다.

## 입력 형식

```jsonc
{
  "title": "탭 제목 2~4단어", "heading": "h1 (생략 시 title)",
  "sub": "부제 — 신뢰 HTML(<b> 등)", "aria": "그림 요약 한 문장 (생략 시 열 순서로 자동)",
  "columns": ["t0 · 계획", "t1", ...],                 // X축 = 시간 순 슬롯. 열이 늘면 폭이 는다(250px/열)
  "lanes": [{ "id": "dev", "name": "개발 팀", "roles": ["역할 이름", "· 보조 줄"], "tone": "dev" }],
  "nodes": [{ "id": "t1", "lane": "dev", "col": 1, "row": 0,
              "bl": "BL-0012", "title": "번호·Task", "sub": "회색 보조 줄", "status": "done|run|wait", "write": true,
              "agent": "claude|codex", "model": "opus", "effort": "low|medium|high|xhigh|max" }],
  "groups": [{ "id": "verify-all", "nodes": ["dr", "cr", "qa"] }],   // 병렬 검증 묶음 → 점선 상자, 연결의 끝점이 될 수 있다
  "edges": [{ "from": "t1", "to": "t2", "label": "High 이상", "loop": true, "merge": true }],
  "notes": [{ "title": "신뢰 HTML", "body": "신뢰 HTML" }]          // 3~4개
}
```

- `tone`: `plan`·`dev`·`verify`·`coord`·`harness` 중 하나(기준 파일의 색 토큰). 생략하면 순서대로. **`harness` 레인 1개 필수** — 회고·하네스 Task가 어디서 도는지 보이게.
- `row`: 레인 안의 워커 행(80px 간격) — 같은 워커의 노드는 같은 `row`. 생략하면 입력 순서로 0, 1, 2…. 소수(0.5)로 이웃 열과 높이를 맞춘다. 레인 높이는 자동.
- `bl`: 백로그 번호. BL이 발급된 Run이면 모든 노드에 넣는다(`docs/backlog.md` 행의 "계획 <Task ID>"로 대조). 아래 규칙 **노드 라벨** 참고.
- `sub`(2번째 줄) = **작업 내용**(backlog 제목에서 Task ID를 뺀 것). 역할·등급·플랫폼·BL 번호를 넣지 않는다 — 각각 레인·아이콘·라벨이 보여 준다. 길어도 자르지 않고 전문을 그대로 쓴다(카드 밖으로 넘쳐도 됨).
- `agent`·`model`·`effort`: 카드 아래 테두리 오른쪽에 걸친 아이콘 태그(✳ Claude / ◎ Codex + effort 작은 글씨 L/M/H/XH/MAX). 모델명은 툴팁. gate처럼 워커가 없으면 생략.
- `write: true`: 외부 데이터(운영 DB·커머스 API 등)를 쓰는 Task. 경고색 굵은 테두리 + 보조 줄 경고색. 메모 카드 하나를 범례로 쓴다(`<span class="key"></span>`).
- `loop: true`: 앞 열로 되돌아가는 연결(재검 등) — 점선, 출발 노드 아래(또는 위) 가운데에서 내려가 대상 오른쪽으로 들어간다.
- `merge: true`: 멀리서 합류하는 연결 — 출발 행을 따라 대상 열 가운데까지 간 뒤 대상 위(또는 아래)로 들어간다.
- 텍스트(`title`·`sub`·레인·열·라벨)는 이스케이프하고 `sub`(부제)·`notes`만 HTML로 넣는다. 사용자·외부 입력을 그 두 필드에 그대로 넣지 않는다.

## 규칙 (기준 파일에서 추출)

- **캔버스:** 고정 px SVG + `.scroll` 가로 스크롤. 축소해서 화면에 맞추지 않는다. mermaid 같은 자동 맞춤 렌더는 쓰지 않는다.
- **Y = 팀 레인:** 팀별 색 띠, 굵은 팀 이름 + 역할 mono 보조 줄. 하네스 레인 필수.
- **X = 시간 순 슬롯:** 열 머리는 `t0`, `t1 · 웨이브 0`처럼 슬롯 번호(+ 필요하면 단계 이름), 열 사이 점선. 단계·주제별로 열을 나누지 않는다. 열 배치 규칙:
  - 같은 열 = 그 시점에 실제로 동시에 진행되는 노드. 팀이 달라도 같은 시점이면 같은 열.
  - 레인 안 `row` 하나 = 워커(또는 리더) 한 명. 한 워커가 차례로 하는 노드는 같은 행의 연속된 열에 놓는다 — 한 워커의 노드 둘이 같은 열에 오면 안 된다. 레인 `roles`에 행별 워커를 적는다(예: "행0 engineer 미러 체인 · 행1 curator 묶음").
  - 노드의 열 = max(선행 노드의 열 + 1, 같은 워커 직전 노드의 열 + 1). 사용자 승인처럼 대기가 끼면 그 대기도 한 슬롯을 차지하는 노드로 둔다.
  - 한 Task가 두 워커로 나뉘면(예: 스킬 부분 · 문서 부분) 노드도 나눈다.
  - 메모 카드 하나는 "읽는 법"(열 = 시간 순, 행 = 워커)으로 쓴다.
- **노드 = 2줄 카드**(190×56): 굵은 제목(번호·Task) + 회색 보조 줄, 상태 텍스트·BL 번호는 아래 노드 라벨. 테두리 = 레인 색, 완료 2.5 + **녹색 테두리**(`--done`, 레인 색 대신 — 쓰기 Task도 테두리는 녹색, 보조 줄 경고색은 유지) · 진행 3 · 대기 점선 + 흐림. 팀 색에는 녹색을 쓰지 않는다(완료와 겹침).
- **노드 라벨**: BL 번호 = 카드 **왼쪽 위 모서리**에 걸친 **사선(-35°)** 태그(60×16, 11px, 레인 색 바탕). 상태는 라벨이 아니라 카드 안 오른쪽 위 **텍스트**(`✓ 완료` 녹색 / `▶ 진행` / `대기` 회색, 13px). 카드 폭 190·2줄 내용은 바꾸지 않는다 — BL을 제목에 붙이거나 카드를 넓히지 않는다. 상태를 라벨로 만들지 않는다.
- **범례:** 렌더러가 부제 아래에 자동으로 그린다 — 쓰인 tone마다 색 견본 + 뜻(`TONE_MEANING`: plan 기획 · dev 제작 · verify 검증 · coord 조정 · harness 하네스) + 그 tone의 레인 이름, 그리고 완료·진행·대기 표시. 레인 `tone`은 이 뜻에 맞춰 고른다(예: 디자인·3D 제작 레인 = `dev`). 한 줄 노드는 쓰지 않는다.
- **쓰기 Task:** 경고색 굵은 테두리 + 보조 줄 경고색.
- **병렬 검증 묶음:** 점선 그룹 상자. 묶음 전체로 나가고 들어오는 연결은 상자 변에 고르게 나눈 점을 쓴다.
- **연결점:** 노드마다 출력점은 오른쪽 가운데 1개, 입력점은 왼쪽 가운데 1개(합류·루프 예외는 위 형식 절).
- **연결선:** 인접 열 = S자 곡선(열 사이 틈 가운데에서 꺾임). 먼 연결 = 출발 행 또는 도착 행을 따라 최단 직각(빈 행이어야 한다). 어떤 연결선도 노드 사각형을 지나지 않는다 — 렌더러가 검사하고 exit 1. 되돌아가는 루프는 점선. 조건이 있는 연결에는 라벨(High 이상·재검·합류 등).
- **메모 카드 3~4개**(그림 아래): 병렬 설명 · 쓰기 범례 · 지금 상태 · 주의.
- **글자:** 레인·제목·보조 줄·라벨 ≥14px. 기준 파일 그대로 상태·부제 `code`만 13px, BL 태그만 11px.
- **테마:** `:root` 토큰 + `prefers-color-scheme: dark`(`:root:not([data-theme="light"])`) + `:root[data-theme="dark"]` 둘 다.

## 검사

```bash
node ~/.claude/skills/dag-swimlane/scripts/render.mjs --self-test
```
`examples/reference.json`이 기준 파일과 같은 수(레인 5·열 9·노드 16·연결 20·그룹 1)로 렌더되고,
`examples/crossing.json`(먼 연결이 노드를 지나는 입력)이 거부되는지 본다. 렌더러를 고치면 이 명령과
브라우저 1회 비교(기준 파일과 나란히, 로컬 http 서버 — `file://`이 막힌 브라우저 도구가 있다)를 다시 한다.

렌더러가 검사하지 않는 것: 연결선끼리의 겹침(두 먼 연결이 같은 열 경계를 쓰면 포개진다 — 한쪽에 `merge`), 라벨-노드 겹침.
먼 연결은 출발 행·도착 행 두 후보만 보고 우회하지 않는다. 둘 다 막히면 exit 1이니 행을 옮긴다.

## 하지 않는 것

- 좌표를 손으로 쓴 SVG를 새로 만들지 않는다 — JSON을 고치고 다시 렌더한다.
- 상태를 다이어그램에만 적지 않는다. 장부가 정본, 그림은 그 사본이다.
- 매 heartbeat마다 재게시하지 않는다. 단계 전환·리더 보고·사용자 요청 때만.
